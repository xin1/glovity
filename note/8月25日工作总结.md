# STM32 + CAN 通信基础学习

> 日期：2026-08-25  
> 主题：CAN 通信、STM32 bxCAN、FIFO、回调函数、指针与内存基础、CAN 收发器

---

## 1. CAN 

CAN 全称：

> **Controller Area Network**

中文：

> **控制器局域网络**

主要用于多个控制器之间通信，常见于汽车 ECU、机器人、电机控制器、工业设备、传感器节点和 BMS。

经典 CAN 的特点：多节点、差分传输、抗干扰能力强、支持仲裁、可靠性高、单帧 Data 最多 8 Byte

---

## 2. CAN 与 FDCAN

### Classic CAN

- 标准 ID：11 bit
- 扩展 ID：29 bit
- 单帧 Data 最多 8 Byte
- 常见最高速率约 1 Mbps

### CAN FD / FDCAN

CAN FD：

> **Controller Area Network Flexible Data-Rate**

特点：

- 单帧数据最多 64 Byte
- 数据阶段可以更快
- 适合更大数据量通信

FDCAN 常用于 STM32 外设名称，例如：

```text
FDCAN1
FDCAN2
```

---

## 3. 标准帧与扩展帧

### 标准帧

CAN ID 长度：11bit

范围：

```text
0x000 ~ 0x7FF
```

例如：

```c
TxHeader.IDE = CAN_ID_STD;
TxHeader.StdId = 0x123;
```

### 扩展帧

CAN ID 长度：

29bit

范围：

```text
0x00000000 ~ 0x1FFFFFFF
```

例如：

```c
TxHeader.IDE = CAN_ID_EXT;
TxHeader.ExtId = 0x18FF50E5;
```

标准帧和扩展帧主要区别是 **ID 长度**，不是 Data 大小。

---

## 4. CAN 有哪些帧

| 类型                    | 作用                           |
| ----------------------- | ------------------------------ |
| 数据帧 Data Frame       | 真正发送数据                   |
| 遥控帧 Remote Frame     | 请求其他节点发送某个 ID 的数据 |
| 错误帧 Error Frame      | 通知总线上出现错误             |
| 过载帧 Overload Frame   | 延迟下一帧发送                 |
| 帧间隔 Interframe Space | 两帧之间的间隔                 |

实际应用中最常见的是 **数据帧**。

---

## 5. CAN 数据帧结构

经典 CAN 数据帧可以粗略理解为：

```text
SOF
 ↓
仲裁段
 ↓
控制段
 ↓
Data
 ↓
CRC
 ↓
ACK
 ↓
EOF
```

主要字段：

| 字段 | 含义                       |
| ---- | -------------------------- |
| SOF  | Start Of Frame，帧开始     |
| ID   | CAN 消息标识符             |
| RTR  | 数据帧 / 遥控帧            |
| IDE  | 标准帧 / 扩展帧            |
| DLC  | Data Length Code，数据长度 |
| Data | 用户真正的数据             |
| CRC  | 错误检测                   |
| ACK  | 接收确认                   |
| EOF  | End Of Frame，帧结束       |

STM32 程序中最常直接操作：

```text
ID
IDE
RTR
DLC
Data
```

SOF、CRC、ACK、EOF 通常由 CAN 硬件自动处理。

---

## 6. DLC 是什么

DLC：

> **Data Length Code**

表示 CAN 数据区有多少字节。

经典 CAN：

```text
DLC = 0 ~ 8
```

例如：

```c
TxHeader.DLC = 8;
```

表示后面有 8 Byte Data。

---

## 7. CAN_H 与 CAN_L

CAN 使用差分信号：

```text
CAN_H
CAN_L
```

接收端关注：

V_{diff}=V_{CANH}-V_{CANL}

典型高速 CAN：

### 隐性位

```text
CAN_H ≈ 2.5V
CAN_L ≈ 2.5V
```

V_{diff}\approx0V

### 显性位

```text
CAN_H ≈ 3.5V
CAN_L ≈ 1.5V
```

V_{diff}\approx2V

---

## 8. STM32 本身有没有 CAN_H / CAN_L

没有。

STM32 芯片本身通常提供：

```text
CAN_TX
CAN_RX
```

它们是 MCU 逻辑侧数字信号。

真正的 CAN_H / CAN_L 需要经过 CAN 收发器：

```text
STM32
│
├── CAN_TX ───→ CAN收发器 TXD
│
├── CAN_RX ←─── CAN收发器 RXD
│
└────────────── CAN收发器
                   │
               CAN_H
               CAN_L
```

---

## 9. STM32F103 的 CAN 引脚

以常见 STM32F103C8T6 为例：

默认 CAN1：

```text
PA11 → CAN_RX
PA12 → CAN_TX
```

还可以通过重映射使用：

```text
PB8 → CAN_RX
PB9 → CAN_TX
```

部分型号还可能支持：

```text
PD0 → CAN_RX
PD1 → CAN_TX
```

具体以芯片型号和封装为准。

主要给 STM32 的 RTC、备份寄存器和备份域供电。

## 11. CAN 收发器是什么

CAN 收发器的核心作用：

> **把 MCU 的 TX/RX 数字逻辑信号转换成 CAN_H/CAN_L 差分信号，反过来也一样。**

常见芯片：

- SN65HVD230
- TJA1050
- TJA1051

例如 SN65HVD230：

```text
STM32                    SN65HVD230

CAN_TX ───────────────→ D / TXD
CAN_RX ←─────────────── R / RXD

                         CANH ─── CAN_H
                         CANL ─── CAN_L
```

其中：

- D = Driver Input，发送输入
- R = Receiver Output，接收输出

可以简单记：

```text
D ≈ TX
R ≈ RX
```

---

### 为什么需要 CAN 收发器

STM32 的普通逻辑引脚处理的是 0V / 3.3V 一类单端数字信号，而 CAN 总线需要：

- 差分驱动
- 总线驱动能力
- 共模电压
- 抗干扰
- 短路保护
- ESD 保护

所以必须：

```text
STM32 CAN_TX/RX
      ↓
CAN 收发器
      ↓
CAN_H / CAN_L
```

---

###  CAN 终端电阻

高速 CAN 总线两端通常各放：

```text
120Ω
```

两个 120Ω 并联：

120\Omega \parallel 120\Omega = 60\Omega

系统断电时测：

```text
CAN_H ↔ CAN_L
```

正常双端终端情况下通常约 60Ω。

## 12. Filter 是什么

```c
CAN_FilterTypeDef filter;
```

其中：

- `CAN_FilterTypeDef`：结构体类型
- `filter`：变量名

作用：

> 创建一份 CAN 过滤规则配置。

调试时常先配置成接收所有 CAN ID。

例如：

```c
filter.FilterIdHigh = 0x0000;
filter.FilterIdLow = 0x0000;
filter.FilterMaskIdHigh = 0x0000;
filter.FilterMaskIdLow = 0x0000;
```

## 13. FIFO 是什么

FIFO：

> **First In First Out**

中文：

> **先进先出**

例如：

```text
消息1 → 先进去
消息2 → 后进去
消息3 → 再进去

取的时候：
消息1 → 最先出来
```

FIFO0 是：

> **STM32 CAN 外设内部自带的硬件接收缓冲区。**

流程：

```text
CAN 总线
   ↓
CAN 控制器
   ↓
Filter
   ↓
FIFO0
   ↓
CPU
```

STM32F103 bxCAN 中：

> FIFO0 可以排队保存最多 3 条完整 CAN 消息。

FIFO1 也可以保存 3 条。

---

### FIFO0 为什么能存数据

因为 CAN 控制器内部有专门的硬件消息缓冲单元。

一条 CAN 接收消息包含：

```text
CAN ID
DLC
IDE
RTR
Data[0~7]
```

FIFO0 可以粗略理解成：

```text
FIFO0
├── 第1帧
├── 第2帧
└── 第3帧
```

经典 CAN 每帧 Data 最多 8 Byte，因此 3 帧的用户 Data 最多：

\[
3\times8=24Byte
\]

但 FIFO0 还保存 ID、DLC 等信息，所以并不是一个普通 24 Byte 数组。

---

### 为什么不能直接把 CAN 数据给 CPU

因为 CPU 不一定正好有空。

所以：

```text
CAN控制器负责“收”
FIFO负责“等”
CPU负责“处理”
```

类比：

```text
CAN消息 = 快递
FIFO0   = 前台暂存区
CPU     = 收件人
```

---

### Filter 和 FIFO 的关系

最重要的一句话：

> **Filter 决定“收不收”，FIFO 决定“收下来放哪”。**

例如：

```c
filter.FilterFIFOAssignment = CAN_RX_FIFO0;
```

表示通过该 Filter 的消息放进 FIFO0。

## 14. 中断与回调的关系

可以记：

> **中断 = “发生事情了，通知 CPU”*

> **回调函数 = “事情发生以后具体执行什么代码”**

CAN 接收：

```text
FIFO0 有数据
   ↓
中断
   ↓
回调函数
   ↓
GetRxMessage()
   ↓
处理数据
```

## 15. CAN 型 IMU 数据解析思路

假设 CAN IMU 发：

```text
CAN ID = 0x123
DLC = 8

Data:
55 51 AxL AxH AyL AyH AzL AzH
```

可能表示：

```text
0x55 → 协议头
0x51 → 加速度数据类型
AxL/AxH → X轴加速度
AyL/AyH → Y轴加速度
AzL/AzH → Z轴加速度
```

---

## 16. 协议头是什么

协议头：

> **协议规定的一段固定标志，用来说明这是一帧符合该应用协议的数据。**

例如厂家可能规定：

```text
0x55
```

是协议头。

注意：

> `0x55` 不是 CAN 标准规定的，而是厂家自己定义的应用协议。

要区分：

```text
CAN ID
↓
哪条消息 / 哪个节点相关

协议头
↓
是不是符合这个厂家协议

数据类型
↓
这一帧是什么数据
```

例如：

```text
CAN ID = 0x202

Data:
55 51 ...
```

可以理解：

```text
0x202 → CAN 消息 ID
0x55  → 协议头
0x51  → 加速度数据
```

---

## 17 AxL、AxH 与 RawX

例如：

```text
AxL = 0x34
AxH = 0x12
```

拼接：

\[
RawX=(AxH<<8)|AxL
\]

所以：

```text
RawX = 0x1234
```

代码：

```c
raw_ax = (int16_t)(
    ((uint16_t)RxData[3] << 8)
    | RxData[2]
);
```

关系：

```text
AxL + AxH
    ↓
RawX
    ↓
厂家换算公式
    ↓
真实 ax
```

## 19. CAN 接收完整流程

把今天最核心的内容串起来：

```text
CAN_H / CAN_L
      ↓
CAN 收发器
      ↓
STM32 CAN_RX
      ↓
CAN 控制器
      ↓
Filter
      ↓
FIFO0
      ↓
FIFO0 有消息
      ↓
触发中断
      ↓
HAL_CAN_RxFifo0MsgPendingCallback()
      ↓
HAL_CAN_GetRxMessage()
      ↓
┌──────────────┬──────────────┐
│ RxHeader     │ RxData       │
│ ID/DLC等     │ Data[0~7]    │
└──────────────┴──────────────┘
      ↓
按协议解析
      ↓
得到实际数据
```

## 20. CAN 接收 Demo

```c
CAN_RxHeaderTypeDef RxHeader;
uint8_t RxData[8];

void HAL_CAN_RxFifo0MsgPendingCallback(CAN_HandleTypeDef *hcan)
{
    HAL_CAN_GetRxMessage(

        CAN_RX_FIFO0,
        &RxHeader,
        RxData
    );

}
```
