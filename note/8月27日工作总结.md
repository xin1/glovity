# 8月27日工作总结

## 一、GPIO 与 I/O 引脚

### 1. I/O 引脚

I/O = **Input / Output，输入 / 输出**。

GPIO = **General Purpose Input/Output，通用输入输出**。

```text
输入：
外部信号 → MCU

例如：
按键 → GPIO → STM32


输出：
MCU → 外部设备

例如：
STM32 → GPIO → LED
```

一个 GPIO 往往可以配置成很多功能：

```text
GPIO
├── 输入
├── 输出
├── UART
├── I2C
├── SPI
├── PWM
└── ADC
```

------

## 二、推挽输出与开漏输出

### 1. 推挽 Push-Pull

内部可以粗略理解成：

```text
       VDD
        |
      PMOS
        |
      GPIO
        |
      NMOS
        |
       GND
```

输出高电平：

```text
PMOS 导通
NMOS 关闭

VDD → GPIO
```

输出低电平：

```text
PMOS 关闭
NMOS 导通

GPIO → GND
```

所以：

> **推挽既可以主动拉高，也可以主动拉低。**

“推挽”的中文含义：

```text
推 → 推向高电平
挽 → 拉向低电平
```

------

### 2. 开漏 Open-Drain

内部主要只有负责拉低的 NMOS：

```text
        3.3V / 5V
            |
         上拉电阻
            |
            +---- GPIO
            |
          NMOS
            |
           GND
```

特点：

```text
输出 0：
NMOS 导通
GPIO → GND

输出 1：
NMOS 关闭
GPIO 自己不输出高电平
依靠上拉电阻变成高电平
```

因此：

> **开漏只能主动拉低，不能主动拉高。**

典型应用：

```text
I2C SDA
I2C SCL
```

------

## 三、PMOS 与 NMOS

MOSFET 主要有：

```text
G = Gate   栅极
S = Source 源极
D = Drain  漏极
```

### PMOS

通常用于高边：

```text
VDD
 |
PMOS
 |
负载
 |
GND
```

对于 PMOS：

```text
Vgs = Vg - Vs
```

当 `Vgs` 足够负时：

```text
PMOS → 导通
```

例如：

```text
Vs = 5V
Vg = 0V

Vgs = -5V
→ 导通
```

### NMOS

通常适合低边：

```text
负载
 |
NMOS
 |
GND
```

一般：

```text
Vgs 足够正
→ NMOS 导通
```

因此推挽电路可以理解成：

```text
PMOS → 负责拉高
NMOS → 负责拉低
```

------

## 四、保护二极管

GPIO 内部通常存在保护结构，可以粗略理解为：

```text
        VDD
         |
      保护二极管
         |
        GPIO
         |
      保护二极管
         |
        GND
```

作用：

> 防止 GPIO 电压过高或者过低损坏芯片内部电路。

正常：

```text
0V ~ 3.3V
```

保护二极管一般不工作。

------

## 五、为什么 GPIO 的 5V 会流向 VDD？

假设：

```text
GPIO = 5V
VDD  = 3.3V
```

GPIO 上方存在保护二极管：

```text
GPIO ---->|---- VDD
```

因为：

```text
GPIO 电压 > VDD 电压
```

并且压差足够大，二极管会正向导通：

```text
5V
 ↓
GPIO
 ↓
保护二极管
 ↓
VDD
```

这叫电流向 VDD **倒灌**。

所以：

> 普通 3.3V GPIO 不能因为有保护二极管就随便接 5V。

------

## 六、开漏外接 5V 时为什么流向 NMOS？

分两种情况。

### NMOS 导通

```text
5V
 |
上拉电阻
 |
GPIO ≈ 0V
 |
NMOS
 |
GND
```

电流：

```text
5V → 电阻 → NMOS → GND
```

此时：

```text
GPIO ≈ 0V
VDD = 3.3V
```

所以 GPIO → VDD 的保护二极管不会导通。

------

### NMOS 关闭

这时：

```text
5V
 |
上拉电阻
 |
GPIO ≈ 5V
```

如果是普通 GPIO：

```text
可能通过保护二极管
→ VDD
```

因此只有满足数据手册要求的：

> **5V tolerant（5V 容忍）GPIO**

才适合拉到 5V。

所以：

> **开漏 ≠ 一定可以接 5V。**

必须看芯片引脚是否支持 5V tolerant。

------

## 七、二极管内部是什么？

普通二极管最核心的结构是：

```text
P 型半导体 | N 型半导体
            ↑
           PN结
```

连接以后形成：

> **耗尽层**

```text
P区       耗尽层       N区
+++++    |      |     -----
```

正向加电：

```text
P 接正
N 接负
```

耗尽层变窄：

```text
→ 容易导通
```

反向加电：

```text
P 接负
N 接正
```

耗尽层变宽：

```text
→ 基本截止
```

普通硅二极管正向压降通常约：

```text
0.6 ~ 0.7V
```

------

## 八、寄存器

寄存器本质上：

> **芯片内部保存二进制状态的小型存储单元。**

里面保存：

```text
0
1
```

这些 0/1 在物理电路上最终通过高低电压状态表示。

但是：

> **寄存器中的 1 不一定代表 GPIO 输出高电平。**

因为要看寄存器功能。

例如：

```text
GPIO ODR bit = 1
→ GPIO 输出高电平
```

但：

```text
TIM CR1 CEN = 1
→ 启动定时器
```

这里的 `1` 只是“开启”。

------

## 九、寄存器与地址

可以类比：

```text
寄存器 = 房间
地址   = 房间号
数据   = 房间里的东西
```

例如：

```text
0x40020014
      ↓
GPIOA_ODR
```

CPU 访问这个地址，就是访问对应寄存器。

关系：

```text
实际寄存器地址
=
外设基地址
+
寄存器偏移地址
```

例如：

```text
GPIOA Base = 0x40020000

ODR Offset = 0x14

GPIOA_ODR
= 0x40020000 + 0x14
= 0x40020014
```

------

## 十、一个地址是不是一个寄存器？

严格来说不是。

STM32 通常是：

> **按字节寻址。**

一个地址对应：

```text
1 Byte = 8 bit
```

如果一个寄存器是：

```text
32 bit = 4 Byte
```

那么可能占：

```text
0x1000
0x1001
0x1002
0x1003
```

四个连续字节地址。

但数据手册通常使用：

```text
0x1000
```

作为这个寄存器的**起始地址**。

------

## 十一、寄存器在哪里？

STM32 中存在不同种类的寄存器。

```text
STM32
│
├── CPU
│   └── CPU寄存器
│       R0、R1、PC、SP...
│
└── 外设
    ├── GPIO寄存器
    ├── UART寄存器
    ├── TIM寄存器
    └── ADC寄存器
```

例如 GPIO 寄存器实际上位于 GPIO 外设硬件内部。

STM32 使用：

> **Memory-Mapped I/O，存储器映射 I/O**

把：

```text
Flash
RAM
GPIO寄存器
UART寄存器
TIM寄存器
```

全部放到统一的地址空间中。

CPU 都可以通过地址访问。

------

## 十二、RAM 与 Flash

### RAM

RAM 是：

> **运行时临时存储器。**

特点：

```text
速度快
可以频繁读写
断电后数据消失
```

例如：

```c
int count;
float angle;
char data[100];
```

运行时很多数据会在 RAM 中。

------

### Flash

Flash：

> **用于长期保存程序和数据。**

特点：

```text
断电以后数据仍然存在
```

STM32 固件主要就在 Flash 里。

------

## 十三、RAM 断电了，为什么再次上电又有数据？

因为：

> **Flash 中保存的程序重新运行，又重新初始化了 RAM。**

例如：

```c
int a = 10;
```

程序上电：

```text
Flash 中保存 a 的初始值 10
        ↓
启动程序执行
        ↓
把 10 放进 RAM
        ↓
a = 10
```

所以不是：

```text
RAM记住了10
```

而是：

```text
Flash里的程序重新把10写进RAM
```

STM32 大概启动过程：

```text
上电
 ↓
复位
 ↓
执行启动代码
 ↓
初始化RAM
 ↓
.data 从Flash复制到RAM
 ↓
.bss 清零
 ↓
进入main()
```

------

## 十四、CPU

CPU：

> **Central Processing Unit，中央处理器。**

主要负责：

```text
读取指令
执行程序
计算
if判断
while循环
读写RAM
访问寄存器
控制外设
```

STM32 里面也有 CPU。

例如 STM32F103 中：

```text
ARM Cortex-M3
```

整个关系：

```text
Flash
 ↓
CPU读取程序
 ↓
执行
 ↓
使用RAM
 ↓
修改外设寄存器
 ↓
控制GPIO等硬件
```

------

## 十五、GPU

GPU：

> **Graphics Processing Unit，图形处理器。**

GPU 更擅长：

```text
大量相似计算
并行运算
矩阵运算
图像处理
深度学习
```

简单区别：

```text
CPU
→ 少量强大的核心
→ 擅长复杂控制和逻辑

GPU
→ 大量计算单元
→ 擅长并行计算
```

因此：

```text
TensorFlow
PyTorch
CUDA
```

经常使用 GPU 加速。

------

## 十六、集显

集显：

> **Integrated GPU，集成 GPU。**

也就是 GPU 被集成在 CPU / SoC 中。

```text
CPU芯片
┌─────────────┐
│ CPU核心     │
│ GPU核心     │
└─────────────┘
```

集显通常：

```text
CPU和GPU共用RAM
```

而独显：

```text
GPU
+
独立显存 VRAM
```

例如：

```text
Intel UHD
AMD Radeon 780M
```

属于常见集显。

RTX 4060 等属于独立显卡。

## 十七、主板

主板：

> **连接电脑各个硬件的主要电路板。**

例如：

```text
主板
├── CPU
├── RAM
├── GPU
├── SSD
├── USB
├── 网卡

```

主板主要承担：

```text
连接
通信
供电
扩展
```

可以把主板理解成：

> **电脑各硬件之间的交通网络。**

------

## 十八、硬盘

硬盘用于：

> **长期保存数据。**

比如：

```text
Windows
软件
代码
照片
视频
文档
```

常见：

```text
硬盘
├── HDD 机械硬盘
└── SSD 固态硬盘
```

### RAM 与硬盘区别

```text
RAM
→ 临时
→ 断电丢失
→ 快

SSD/HDD
→ 长期保存
→ 断电不丢
→ 相对慢
```

可以类比：

```text
硬盘 = 书架
RAM  = 书桌
CPU  = 坐在书桌前工作的人
```

程序运行：

```text
SSD
 ↓
加载到RAM
 ↓
CPU执行
```

## 十九、中断

中断可以理解成：

> **CPU 正在运行程序时，突然发生重要事件，CPU 暂时停止当前任务，先处理这个事件。**

例如：

```text
CPU运行程序
   ↓
按键按下
   ↓
产生中断
   ↓
CPU暂停当前程序
   ↓
处理中断
   ↓
处理完成
   ↓
继续原来的程序
```

### 中断与轮询

轮询：

```text
按了吗？
没按。

按了吗？
没按。

按了吗？
按了。
```

CPU 不断检查。

中断：

```text
CPU去干别的

按键：
“我被按了！”

CPU再回来处理
```

STM32 中：

```text
硬件事件
 ↓
中断请求
 ↓
NVIC
 ↓
CPU进入ISR
 ↓
执行中断服务程序
 ↓
返回原程序
```

常见：

```text
GPIO中断
UART中断
定时器中断
CAN中断
DMA中断
ADC中断
```

## 二十、哈希函数

哈希函数：

> **把任意长度的数据转换成固定长度的“数字指纹”。**

例如：

```text
"hello"
   ↓
SHA-256
   ↓
一串固定长度哈希值
```

特点：

```text
相同输入
→ 相同哈希

输入改变一点
→ 哈希值通常变化很大

正向计算容易
→ 反推原数据困难
```

常见：

```text
MD5
SHA-1
SHA-256
SHA-512
```

用途：

```text
文件完整性校验
密码存储
数字签名
哈希表
```

Python：

```python
dict
```

底层就大量依赖哈希表。

## 二十一、固件与烧录

固件可以理解成：

> **运行在嵌入式设备上的程序。**

例如 STM32 中：

```text
你的C代码
 ↓
编译
 ↓
生成机器代码
 ↓
烧录到Flash
 ↓
STM32上电
 ↓
CPU执行
```

### STM32 烧录

常见：

```text
STM32CubeIDE
    ↓
Build 编译
    ↓
ST-LINK
    ↓
SWD
    ↓
STM32 Flash
```

常见 SWD：

```text
SWDIO
SWCLK
GND
电源参考
```

### Build、Run、Debug

```text
Build
→ 只编译

Run
→ 编译 + 烧录 + 运行

Debug
→ 编译 + 烧录 + 调试
```

如果出现：

```text
Target no device found
```

说明：

> ST-LINK 没有正常找到 STM32。

优先检查：

```text
开发板供电
GND
SWDIO
SWCLK
ST-LINK连接
目标芯片
```

## 今天知识的整体关系

你今天实际上已经把**从电路底层到程序运行**的一条链串起来了：

```text
PN结
 ↓
二极管
 ↓
MOS管
 ↓
PMOS / NMOS
 ↓
推挽 / 开漏
 ↓
GPIO
 ↓
寄存器
 ↓
地址
 ↓
CPU
 ↓
RAM / Flash
 ↓
程序运行
 ↓
中断
 ↓
固件烧录
```

再往电脑层面扩展：

```text
电脑
├── CPU     → 执行程序、控制
├── GPU     → 并行计算
│   ├── 集显
│   └── 独显
├── RAM     → 临时数据
├── SSD/HDD → 长期数据
└── 主板    → 把所有硬件连接起来
```

### 今天最核心的 10 句话

1. **GPIO 是 MCU 与外界交互的输入输出接口。**
2. **推挽可以主动拉高，也可以主动拉低。**
3. **开漏只能主动拉低，高电平依赖上拉电阻。**
4. **PMOS 常用于高边，NMOS 常用于低边。**
5. **二极管的核心结构是 PN 结。**
6. **寄存器里的 0/1 是芯片内部的数字逻辑状态。**
7. **地址告诉 CPU“数据或寄存器在哪里”。**
8. **RAM 断电丢数据，Flash 断电仍保存数据。**
9. **CPU 执行 Flash 中的程序，并利用 RAM 和寄存器完成工作。**
10. **烧录就是把编译后的程序写入 MCU 的 Flash。**

基本形成了 **“电路 → 芯片 → 存储 → CPU → 程序”** 的完整基础框架。
