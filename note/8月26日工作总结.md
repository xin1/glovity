# 五、PB6、PB7 的 GPIO 不需要自己改吗？

通常 CubeMX 会自动配置。

I2C 引脚需要：

```text
PB6
Mode:
Alternate Function Open Drain

PB7
Mode:
Alternate Function Open Drain
```

这个：

> **Open Drain = 开漏输出**

是 I2C 必须的特性之一。

因为 I2C：

```text
SDA
SCL
```

需要通过上拉电阻保持高电平。

# 六、注意 I2C 上拉电阻

这一点很重要。

I2C 总线大概是：

```text
              3.3V
                │
              4.7K
                │
PB6 SCL ────────┼──── MPU9250 SCL


              3.3V
                │
              4.7K
                │
PB7 SDA ────────┼──── MPU9250 SDA
```

一般 MPU9250 模块板上已经有：

```text
4.7kΩ
或者
10kΩ
```

的上拉电阻。

所以如果你买的是完整的 MPU9250 模块：

```text
VCC
GND
SCL
SDA
```

大多数情况下直接接就行。

如果是裸 MPU9250 芯片，就一定要自己考虑上拉。

# 七、MPU9250 接线

推荐：

| MPU9250 | STM32F103C8T6 | 作用     |
| ------- | ------------- | -------- |
| VCC     | 3.3V          | 电源     |
| GND     | GND           | 地       |
| SCL     | PB6           | I2C时钟  |
| SDA     | PB7           | I2C数据  |
| AD0     | GND           | 地址选择 |

这样：

```text
AD0 = 0
```

MPU9250 I2C 地址：

```text
0x68
```

如果：

```text
AD0 = 1
```

地址就是：

```text
0x69
```

# 八、为什么 STM32 代码里写 `(0x68 << 1)`

这个你后面一定会遇到。

MPU9250 数据手册说：

```text
设备地址 = 0x68
```

但是 STM32 HAL：

```c
HAL_I2C_Mem_Read()
```

传进去的设备地址需要左移一位。

所以：

```c
#define MPU9250_ADDR (0x68 << 1)
```

实际上就是：

```text
0x68
=
0110 1000

左移1位

1101 0000
=
0xD0
```

因此以后：

```c
HAL_I2C_Mem_Read(
    &hi2c1,
    0x68 << 1,
    ...
);
```

这是正常的。

不要看到：

```text
0xD0
```

就以为 MPU9250 地址变了。

# 十八、先不要写完整 MPU9250 算法

这一步我非常建议你只测试：

```text
WHO_AM_I
```

因为 MPU9250 有一个寄存器：

```text
地址：
0x75

名称：
WHO_AM_I
```

正常 MPU9250 返回：

```text
0x71
```

所以：

```text
STM32
 ↓
读取0x75
 ↓
返回0x71
```

就说明：

```text
供电 OK
接线 OK
I2C OK
地址 OK
MPU9250 OK
```

# 十九、先写最简单的 WHO_AM_I Demo

在：

```c
/* USER CODE BEGIN 2 */
```

里面写：

```c
uint8_t whoAmI = 0;

HAL_StatusTypeDef status;

status = HAL_I2C_Mem_Read(
    &hi2c1,

    (0x68 << 1),

    0x75,

    I2C_MEMADD_SIZE_8BIT,

    &whoAmI,

    1,

    100
);
```

这里逐个解释：

```text
&hi2c1
│
└── 使用 I2C1


0x68 << 1
│
└── MPU9250 地址


0x75
│
└── WHO_AM_I 寄存器


I2C_MEMADD_SIZE_8BIT
│
└── MPU9250寄存器地址是8bit


&whoAmI
│
└── 把读取的数据放这里


1
│
└── 读取1 Byte


100
│
└── 超时100ms
```

# 二十、暂时不用 printf，先调试看

其实学习 STM32 的话，我反而建议你第一次先别配置 `printf()`。

写：

```c
volatile uint8_t whoAmI = 0;
volatile HAL_StatusTypeDef i2cStatus;
```

然后：

```c
i2cStatus = HAL_I2C_Mem_Read(
    &hi2c1,
    (0x68 << 1),
    0x75,
    I2C_MEMADD_SIZE_8BIT,
    (uint8_t *)&whoAmI,
    1,
    100
);
```

在这一行后面打断点。

进入：

```text
Debug
```

然后看：

```text
Variables
```

如果：

```text
i2cStatus = HAL_OK

whoAmI = 0x71
```

成功。

这是非常干净的第一次测试。

# 二十二、推荐你现在的 CubeMX 最终配置

你可以直接对照：

| 模块      | 配置                      |
| --------- | ------------------------- |
| MCU       | STM32F103C8T6             |
| SYS Debug | Serial Wire               |
| RCC HSE   | Crystal/Ceramic Resonator |
| SYSCLK    | 72 MHz                    |
| I2C1      | Enabled                   |
| I2C1 SCL  | PB6                       |
| I2C1 SDA  | PB7                       |
| I2C速度   | 100 kHz                   |
| USART1    | Asynchronous              |
| USART1 TX | PA9                       |
| USART1 RX | PA10                      |
| 波特率    | 115200                    |
| 数据位    | 8                         |
| 停止位    | 1                         |
| 校验      | None                      |

最终硬件：

```text
                  MPU9250
                ┌────────┐
3.3V ───────────┤ VCC    │
GND ────────────┤ GND    │
PB6 ────────────┤ SCL    │
PB7 ────────────┤ SDA    │
GND ────────────┤ AD0    │
                └────────┘


STM32F103C8T6
      │
      │
      ├── PB6 ─── SCL
      │
      ├── PB7 ─── SDA
      │
      │
      ├── PA9 ─── UART TX
      │
      └── PA10 ── UART RX
```

### 顺序

```text
① CubeMX配置 I2C1
        ↓
② 配置 USART1
        ↓
③ 生成代码
        ↓
④ 只读取 0x75
        ↓
⑤ 检查 WHO_AM_I 是否等于 0x71
        ↓
⑥ 读取 ax ay az
        ↓
⑦ 读取 gx gy gz
        ↓
⑧ 做零偏
        ↓
⑨ Gyro积分
        ↓
⑩ Acc计算姿态
        ↓
⑪ 互补滤波
        ↓
⑫ Mahony
```

先确保 `HAL_I2C_Mem_Read()` 能从 `0x75` 读出 `0x71`。这一步会把你后面“驱动问题”和“IMU算法问题”彻底分开，调试起来会容易很多。
