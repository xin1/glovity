## PNP

### 重点代码理解与注释

```python
def solve_square_marker_pose(
    image_corners: np.ndarray,
    #ArUco 检测得到的 Marker 四个角点的 2D 像素坐标
    object_points: np.ndarray,
    #Marker 四个角点在 Marker 自身坐标系中的 3D 坐标
    calibration: CameraCalibration,
    #相机标定参数，包括相机内参矩阵 K 和畸变参数
) -> MarkerPose | None:
    #MarkerPose，里面包含旋转向量、平移向量、重投影误差
    """Solve both planar candidates and keep the best positive-depth pose."""

    result = cv2.solvePnPGeneric(
        # 调用 OpenCV 的 PnP 求解函数。
        objectPoints=object_points,
        # Marker 四个角点的 3D 坐标。
        imagePoints=np.asarray(image_corners, dtype=np.float64).reshape(4, 2),
        # Marker 在摄像头图像中检测到的四个角点。
        cameraMatrix=calibration.camera_matrix,
        # 相机内参矩阵 K。
        distCoeffs=calibration.distortion_coefficients,
        # 相机镜头畸变参数。
        flags=cv2.SOLVEPNP_IPPE_SQUARE,
        # 指定 PnP 使用的具体求解算法：IPPE_SQUARE
    )
    success, rotation_vectors, translation_vectors = result[:3]
    # solvePnPGeneric 会返回多个数据，只取前三个。
    if not success:
        return None

    candidates: list[MarkerPose] = []
    # 创建一个列表用来保存所有“有效的 PnP 候选姿态”。
    for rotation_vector, translation_vector in zip(rotation_vectors, translation_vectors):
        # rvec + tvec
        rotation_vector = np.asarray(rotation_vector, dtype=np.float64).reshape(3)
        # 将旋转向量转换为长度为 3 的数组， [rx, ry, rz]。
        translation_vector = np.asarray(translation_vector, dtype=np.float64).reshape(3) 
        # 将平移向量整理成：[tx, ty, tz]表示 Marker 原点相对于摄像头的位置。
        rotation, _ = cv2.Rodrigues(rotation_vector)
        # Rodrigues 变换：把 PnP 输出的旋转向量 rvec，转换成 3×3 旋转矩阵 R。
        camera_points = (rotation @ object_points.T).T + translation_vector
        # Pc = R × Pw + t
        if np.any(camera_points[:, 2] <= 0.0):
            # 检查所有 Marker 角点的 Z 坐标是否<=0。
            continue
        projected, _ = cv2.projectPoints(
            # 这里进行“重投影”。
            object_points,
            rotation_vector,
            translation_vector,
            calibration.camera_matrix,
            calibration.distortion_coefficients,
        )
        residuals = projected.reshape(4, 2) - np.asarray(image_corners).reshape(4, 2)
        # 计算“重投影残差”。
        rmse = float(np.sqrt(np.mean(np.sum(np.square(residuals), axis=1))))
        # 均方根误差
        candidates.append(MarkerPose(rotation_vector, translation_vector, rmse))
        # 将当前这个有效候选解保存起来。
    return min(candidates, key=lambda pose: pose.reprojection_rmse_px, default=None)
	# 找到 reprojection_rmse_px 最小的那个。
```

其中flags=cv2.SOLVEPNP_**IPPE_SQUARE**

还可选用以下这些：

| 方法            | OpenCV 标志            | 适合场景                  | 简单理解                           |
| --------------- | ---------------------- | ------------------------- | ---------------------------------- |
| **ITERATIVE**   | `SOLVEPNP_ITERATIVE`   | 通用场景、点较多          | 不断优化姿态，让重投影误差越来越小 |
| **EPNP**        | `SOLVEPNP_EPNP`        | 多个 3D-2D 点、速度要求高 | Efficient PnP，计算快              |
| **P3P**         | `SOLVEPNP_P3P`         | 少量点                    | 用少量点直接求多个候选姿态         |
| **AP3P**        | `SOLVEPNP_AP3P`        | 少量点                    | P3P 的另一种快速算法               |
| **IPPE**        | `SOLVEPNP_IPPE`        | 一般平面目标              | 专门处理所有点共面的情况           |
| **IPPE Square** | `SOLVEPNP_IPPE_SQUARE` | **正方形平面 Marker**     | ArUco、AprilTag 特别适合           |
| **SQPnP**       | `SOLVEPNP_SQPNP`       | 通用 PnP                  | 一种较新的全局最优求解方法         |

### 对pnp中数值的理解

![一文详解PnP算法原理](https://picx.zhimg.com/70/v2-86bcae01e3787b00a192dc7e92ec7dca_1440w.image?source=172ae18b&biz_tag=Post)

可以把 PnP 想成一个“**看照片猜这个正方形在空间里怎么摆**”的问题，就很容易理解了。

你现在已经知道这个 Marker 在现实中是一个**固定大小的正方形**，比如边长 10 cm。也就是说，PnP 事先知道它四个角在自身坐标系里的 3D 坐标：

```text
左上 ●────────● 右上
     │        │
     │ Marker │
     │        │
左下 ●────────● 右下
```

假设中心是 `(0,0,0)`，四个角可以是：

```text
左上 (-5, +5, 0)
右上 (+5, +5, 0)
右下 (+5, -5, 0)
左下 (-5, -5, 0)
```

这就是你代码里的 `object_points`。

然后摄像头拍到它以后，ArUco 检测算法会告诉你：

```text
左上角现在在图片 (u1,v1)
右上角现在在图片 (u2,v2)
右下角现在在图片 (u3,v3)
左下角现在在图片 (u4,v4)
```

也就是：

```text
现实中的 4 个已知点
        ↓
   摄像头拍照
        ↓
照片里的 4 个像素点
```

假设 Marker 正对着摄像头：

```text
┌─────────┐
│         │
│ Marker  │
│         │
└─────────┘
```

摄像头看到的也是一个比较标准的正方形。

PnP 就会判断：

> 它应该基本正对着我。

------

如果 Marker 向右转了一点

```
A│\
 │ \
 │  \
 │   │B
 │   │
 │   │C
 │  /
 │ /
D│/
```

图像中的正方形变成了一个类似梯形的形状。

左边看起来宽，右边看起来窄。

PnP 就可以从这种**透视变形**判断：

> 这个 Marker 往右转了。

于是得到旋转，也就是 `R / rvec`。

------

再比如 Marker 离摄像头很远：

```text
    ┌─────┐
    │     │
    └─────┘
```

它在图片里会很小。

Marker 离摄像头近：

```text
┌───────────────┐
│               │
│               │
|               |
└───────────────┘
```

它在图片里就会很大。

由于 PnP **知道这个 Marker 现实中的真实尺寸**，比如就是 10 cm，所以它可以判断：

> 一个真实 10 cm 的东西，现在在图片里只有这么大，那它应该距离摄像头大约这么远。

所以算出了：

```text
tz = 前后距离
```

------

同样，如果 Marker 出现在画面右边：

```text
摄像头画面

┌───────────────────┐
│                   │
│             □     │
│                   │
└───────────────────┘
```

PnP 就会知道：

```text
tx > 0
```

说明它在摄像头右边。

如果出现在画面上方，就可以推测 `ty`。

因此最终得到：

```text
tx → 左右
ty → 上下
tz → 前后
```

这就是**位置**。

**但这里有个关键问题**

你可能会想：

> 我只知道图片里面几个像素的位置，它怎么知道空间距离？

关键就在于**相机内参**。

你可以把相机内参理解成：

> PnP 必须提前知道这个摄像头“怎么看世界”。

比如它要知道：

```text
焦距 fx fy
图像中心 cx cy
镜头畸变
```

因为两个摄像头即使拍同一个东西：

```text
广角摄像头：     □ 看起来比较小

长焦摄像头：   ███ 看起来比较大
```

如果不知道摄像头自己的参数，仅凭图片大小，是没法准确判断距离的。

所以 PnP 实际拿到的是：

```text
① Marker真实长什么样
   ↓
4个3D点

② 摄像头现在看到什么
   ↓
4个2D点

③ 这个摄像头本身什么参数
   ↓
相机内参 K

        三者一起
           ↓
          PnP
           ↓
      Marker 的 R + t
```

你的代码就是把这三个东西塞给 PnP：

```python
cv2.solvePnPGeneric(
    objectPoints=object_points,       # 现实中4个角的位置
    imagePoints=image_corners,        # 图片中4个角的位置
    cameraMatrix=camera_matrix,       # 摄像头参数
    distCoeffs=distortion,            # 镜头畸变
)
```

### PnP 内部在干什么

 在OpenCV 的 `cv2.solvePnPGeneric()` 函数内部

可以把它想象成 PnP 在疯狂“试姿势”。

比如它猜：

```text
第一次猜：

Marker 距离摄像头 50cm
向右旋转 20°
```

然后它模拟：

> 如果 Marker 真的是这个姿势，那么把这四个 3D 角点投影到照片上，应该落在哪里？

得到：

```text
预测角点 ●

实际角点 ×

×   ●
        × ●
```

发现对不上。

于是换一个：

```text
距离：47cm
右转：17°
上移：2cm
```

重新投影。

越来越接近：

```text
×≈●      ×≈●


×≈●      ×≈●
```

当四个预测角点和实际检测角点最接近时：

> 好，这个 `R + t` 应该就是 Marker 的真实姿态。

你代码后面的 `projectPoints()` + `RMSE`，本质上就是在检查这件事情：

```text
真实检测角点
      ↑
      │ 比较误差
      ↓
PnP姿态重新投影出来的角点
```

误差越小，这个姿态越靠谱。

### 最终所得两个数据R&T

```text
             PnP
              │
        ┌─────┴─────┐
        ↓           ↓
      rvec         tvec
      旋转          平移
        ↓           ↓
   朝哪个方向     在哪里
```

例如：

```text
tvec = [0.10, -0.05, 0.50]
```

可以粗略理解成 Marker：

```text
右边 10 cm
上/下方向 5 cm
前方 50 cm
```

而：

```text
rvec
```

描述 Marker 是怎样旋转的，之后再通过：

```python
cv2.Rodrigues(rvec)
```

变成旋转矩阵 `R`，再进一步可以转换成：

```text
Roll
Pitch
Yaw
```
