## 二、马达模块

### ERM 偏心转子马达

#### 1. 基本信息

ERM（Eccentric Rotating Mass）偏心转子马达是一种常见的小型振动执行器。

本次使用的是：

- **型号形式**：0820 带线微型振动马达
- **线长**：约 3 cm
- **驱动模块接口**：
  - IN：控制信号输入
  - VCC：电源输入
  - GND：电源地
- **控制方式**：PWM 调速控制

ERM 的核心结构是在普通直流电机轴上安装一个偏心配重块。电机旋转时，由于重心不在旋转轴中心，会产生周期性离心力，从而带动整个马达产生振动。

| 特点 | 说明                     |
| ---- | ------------------------ |
| 优点 | 体积小、成本低、控制简单 |
| 缺点 | 响应慢、精度有限、功耗高 |

#### 2. PWM 控制效果

通过调节 PWM 占空比，可以改变马达的平均输入功率和转速，从而改变振动强度。

测试效果大致如下：

| PWM 占空比 | 振动效果 |
| ---------- | -------- |
| 40%        | 轻微震感 |
| 60%        | 中等震感 |
| 100%       | 强烈震感 |

随着 PWM 占空比增大，马达转速通常会上升，振动强度也会增强。

需要注意的是，ERM 的振动强度和 PWM 占空比通常**不是严格线性关系**。当占空比较低时，可能由于启动转矩不足而无法正常旋转，因此实际使用时一般需要通过实验确定最低有效占空比。

### LRA线性谐振马达与JW BLE DL500 驱动器使用 

适用于已连接单通道 LRA 马达的调试。

**使用结论：**驱动器使用 3.0-5.0 V 供电。首次运行应先固定马达并检测谐振频率 F0，再从较低振幅开始试振。频率决定马达是否处于高效振动状态，振幅决定力度，周期和 ON/OFF 时间决定持续时间与节奏。未知马达规格时不得直接启用高压模式。

#### 2. 首次使用流程

1. 确认马达两根线接在 `LRA+` 和 `LRA-`。LRA 输出为差分交流信号，两端都不是 GND。
2. 使用 USB Type-C 5 V 电源给 Demo 板供电。若从 `VIN` 和 `GND` 供电，电压必须处于 3.0-5.0 V。不要同时从两处供电。
3. 在微信中打开小程序“极路驱动-精微泰锐”，允许蓝牙权限并连接名称类似 `JW-aLRA-xxxx` 的设备。
4. 点击“供电电压”，确认测量值接近实际输入电压。
5. 将马达固定在实际安装位置，点击“马达 F0 频率”。检测完成后，驱动器会把频率调整到检测值。
6. 确认处于普通输出模式，将振幅先设为 20-30，短振周期设为 8-16，然后点击“设置”。
7. 点击“短振”测试。力度不足时每次增加 5；出现撞击声、尖锐异响或明显发热时立即停止并降低振幅。

#### 3. 参数意义和体感

**核心关系：**体感取决于频率与 F0 的接近程度、振幅、振动时长、ON/OFF 节奏和安装结构。下述体感是调试起点，最终结果应以实际马达和结构为准。

##### 振动频率

设置范围为 20-500 Hz。频率不是越高越强。LRA 在 F0 附近振动最强、启停最干净且效率最高。

假设检测得到 F0 为 350 Hz，可参考下表：

| 相对 F0 设置    | 典型表现               | 用途建议           |
| --------------- | ---------------------- | ------------------ |
| 低 15-20 Hz     | 偏软偏沉，力度明显下降 | 仅用于尝试柔和效果 |
| 低 5-10 Hz      | 略柔和，仍有较清楚反馈 | 柔和按键           |
| F0 附近         | 最强、最饱满、效率最高 | 默认设置和强反馈   |
| 高 5-10 Hz      | 略清脆，但通常开始变弱 | 轻微改变质感       |
| 偏离 20 Hz 以上 | 明显变弱，可能只剩噪音 | 不建议作为增强调节 |

不同马达的 F0 不同，不能固定照搬 350 Hz。把频率设到 500 Hz 通常不会更强。

##### 振幅1和振幅2

振幅范围为 1-127。振幅1和振幅2是两组力度预设，分别供 `IO1` 和 `IO2` 触发使用，不代表两个马达，也不会相加。

普通输出的近似关系：

```text
Vpp ≈ 0.0651 × 振幅值 + 0.2038
Vrms ≈ Vpp ÷ 2.828
```

以手册中的 1040 马达测试数据为参考：

| 振幅 | 手册测试 Vpp |  约 Vrms | 直观体感与风险               |
| ---: | -----------: | -------: | ---------------------------- |
|   10 |       0.76 V |   0.27 V | 很轻，安装较松时可能感觉不到 |
|   20 |       1.52 V |   0.54 V | 微弱提示或轻触               |
|   30 |       2.13 V |   0.75 V | 柔和且明确                   |
|   40 |       2.89 V |   1.02 V | 清晰的按键反馈               |
|   50 |       3.50 V |   1.24 V | 较扎实和明显                 |
|   60 |       4.11 V |   1.45 V | 强反馈                       |
|   80 |       5.40 V |   1.91 V | 很强，应确认马达额定电压     |
|  100 |       6.85 V |   2.42 V | 非常强，可能撞击或发热       |
|  120 |       7.99 V |   2.82 V | 接近普通输出极限             |
|  127 |     约 8.3 V | 约 2.9 V | 最大档，不宜盲目持续运行     |

> 马达数据表通常标注 Vrms，应将额定 Vrms 与输出 Vrms 比较，不能把额定 Vrms 直接与 Vpp 比较。表中数据来自 1040 马达在手册测试条件下的结果，其他马达会有差异。

##### 短振周期

范围为 1-225 个正弦波周期。它控制一次短振持续多久，不直接改变每个周期的电压。

```text
短振时间(ms) = 周期数 ÷ 频率(Hz) × 1000
```

假设频率为 175 Hz：

| 周期数 | 理论时长 | 直观体感         |
| -----: | -------: | ---------------- |
|      4 |  22.9 ms | 很轻的小咔哒     |
|      6 |  34.3 ms | 轻触键           |
|      8 |  45.7 ms | 干脆点击         |
|     12 |  68.6 ms | 标准按键反馈     |
|     16 |  91.4 ms | 明显且饱满的一下 |
|     25 | 142.9 ms | 较重的单次冲击   |
|     36 | 205.7 ms | 短促提醒         |
|     50 | 285.7 ms | 接近短嗡声       |
|    100 |   571 ms | 明显持续振动     |
|    225 |  1286 ms | 单次短振最长档   |

手册注明周期值优先选用 1-15 内两个因数的乘积。常用值包括：`4`、`6`、`8`、`9`、`10`、`12`、`15`、`16`、`20`、`25`、`30`、`36` 和 `50`。

##### 长振 ON 时间 OFF 时间和周期

| 参数     | 范围       | 作用和体感                                                   |
| -------- | ---------- | ------------------------------------------------------------ |
| ON 时间  | 10-5000 ms | 每轮实际振动时间。30-120 ms 为脉冲，300-500 ms 为短嗡声，3-5 秒接近持续输出。 |
| OFF 时间 | 10-5000 ms | 两次振动之间的停顿。10-30 ms 几乎连续，50-100 ms 为快速脉冲，120-200 ms 有明显心跳感。 |
| 长振周期 | 1-10 次    | ON/OFF 模式重复次数。总时间约为周期数乘以 ON 与 OFF 时间之和。 |

UART 中的 `SET_ON_TIME` 和 `SET_OFF_TIME` 输入单位为 10 ms。例如发送数值 `50` 代表 500 ms；小程序界面通常直接显示毫秒值。

##### 普通输出和高压输出

- 普通输出最高约 8.3 Vpp，首次调试及未知马达规格时应使用此模式。
- 高压模式最高约 22.2 Vpp，输出电压大幅增加。未确认马达额定电压、最大 Vrms 和允许工作时间前不得启用。

#### 4. 推荐体感参数

所有方案都应先检测 F0，并将频率设为检测值。下表示例假设 F0 为 175 Hz，输出模式为普通输出。

| 效果       |  振幅 | 短振或长振设置                 | 体感                         |
| ---------- | ----: | ------------------------------ | ---------------------------- |
| 柔和触摸   |    25 | 短振周期 6                     | 约 34 ms，适合菜单切换或轻触 |
| 清脆按键   |    45 | 短振周期 14                    | 约 80 ms，清晰但不拖尾       |
| 重力单击   |    65 | 短振周期 22                    | 约 126 ms，明显的咚感        |
| 双脉冲心跳 |    55 | ON 90 ms，OFF 120 ms，周期 2   | 两次分明的脉冲               |
| 强力提醒   |    70 | ON 250 ms，OFF 150 ms，周期 3  | 三次强提醒                   |
| 近似连续   | 30-40 | ON 5000 ms，OFF 10 ms，周期 10 | 约 50 秒，间断通常不明显     |

#### 5. 持续输出和最大输出

##### 真正持续输出

真正无时限的持续输出应使用 `IO1` 或 `IO2` 低电平触发。保持低电平时持续振动，释放为高电平时停止。外部 MCU 应与驱动器共地，并优先使用开漏输出。

| 引脚 | 低电平时的功能                                   |
| ---- | ------------------------------------------------ |
| IO1  | 按振幅1持续输出                                  |
| IO2  | 按振幅2持续输出                                  |
| Key  | 短周期或 ON/OFF 路径触发，具体行为与固件设置有关 |

小程序长振的最大单次配置为 ON 5000 ms、OFF 10 ms、周期 10，约可运行 50 秒，但不属于无限持续输出。

##### 最大力度设置

- 频率设为实际检测到的 F0。把频率设到 500 Hz 通常不会更强。
- 普通输出下，振幅1或振幅2最大可设为 127。
- 建议按 `60 → 80 → 100 → 120 → 127` 分级测试，每级只测试几秒并观察声音、温升和机械撞击。
- 手册的 1040 马达测试中，振幅 125 时瞬时输入电流接近 0.9 A。高力度测试建议使用稳定的 5 V、1 A 或更高能力电源。
- 未知马达规格时，普通输出加振幅 127 已经属于风险测试，不得继续启用高压模式。

#### 正式程序与简单程序的区别

日常只使用 `calibrate_magnetometer.py`。它拟合正定完整 `3×3` 椭球矩阵，包含轴间耦合修正、稳健异常点处理、质量报告和 Arduino 头文件同步。

### 常见问题

- **启动后姿态跳动**：重新启动，前三秒不要移动设备。
- **Yaw 方向不正确**：当前默认是 `--mag-map y,-x,-z`；其他硬件方向可显式覆盖。
- **校准质量失败**：远离磁铁、电机和大电流导线，重新缓慢覆盖完整球面。
- **更换硬件后结果异常**：每颗磁力计和每块 PCB 都应独立重新校准。
- **快速转动后回正较慢**：快速动作时加速度不再只表示重力，融合器会暂时降低加速度计的可信度；陀螺仪量程不足、积分项累积，以及磁力计低通或纠偏带宽较低也会延长恢复时间。早期 `±500 °/s` 日志中三个陀螺轴均出现削顶，当前已改为 `±2000 °/s`。
- **调整 `Kp/Ki`**：`Kp`太小会使回正较慢，太大容易抖动；`Ki`太小会使长期零偏修正不足，太大可能累积错误并引起振荡或持续漂移。
- **更换硬件后结果异常**：每颗磁力计和每块 PCB 都应独立重新校准。

### 2. ESP32-S3 与 IMU761 基本连接

当前使用的 UART 为：

```text
UART1 → TX GPIO17 / RX GPIO18
```

接线关系：

```text
ESP32-S3 GPIO17 TX → IMU761 RXD1
ESP32-S3 GPIO18 RX ← IMU761 TXD1

ESP32-S3 GND       → IMU761 GND
IMU 电源           → IMU761 VIN
```

UART 必须交叉连接：

```text
主机 TX → 设备 RX
主机 RX ← 设备 TX
```

IMU761 的 UART 为 TTL 3.3V 电平。

### 3.使用UART连接一个IMU

**uart**  esp32-s3

UART候选1  → TX GPIO4  / RX GPIO5
UART候选2  → TX GPIO6  / RX GPIO7
UART候选3  → TX GPIO8  / RX GPIO9
UART候选4  → TX GPIO10 / RX GPIO11
UART候选5  → TX GPIO12 / RX GPIO13
UART候选6  → TX GPIO14 / RX GPIO15
UART候选7  → TX GPIO16 / RX GPIO17
UART候选8  → TX GPIO18 / RX GPIO21
UART候选9  → TX GPIO38 / RX GPIO39
UART候选10 → TX GPIO47 / RX GPIO48

UART0默认 → TX GPIO43 / RX GPIO44

其他GPIO接口：

GPIO33～GPIO37 ：都会参与 Flash/PSRAM 通信 ， 当使用 Octal SPI/OPI Flash 或 PSRAM 时，可能与其冲突

GPIO3、GPIO45、GPIO46：GPIO45 是 Strapping Pin，是启动配置脚，不推荐

GPIO39～GPIO42 ：标为和 JTAG 默认功能有关，但该功能暂不需要，可以用

GPIO40：可用但无多余接口配对

```c++
#include <Arduino.h>

HardwareSerial IMU(1);

// ================================
// ESP32-S3
// ================================
#define IMU_TX       17
#define IMU_RX       18

// IMU 总电源
#define IMU_POWER    42

#define IMU_BAUD     115200

// 当前 ID
#define OLD_ID       0x50

// 要修改成的新 ID
#define NEW_ID       0x51


// ====================================================
// Modbus CRC16
// ====================================================
uint16_t modbusCRC(const uint8_t *data, uint16_t len)
{
  uint16_t crc = 0xFFFF;

  for (uint16_t i = 0; i < len; i++)
  {
    crc ^= data[i];

    for (uint8_t j = 0; j < 8; j++)
    {
      if (crc & 0x0001)
      {
        crc >>= 1;
        crc ^= 0xA001;
      }
      else
      {
        crc >>= 1;
      }
    }
  }

  return crc;
}


// ====================================================
// 清空 UART
// ====================================================
void clearIMU()
{
  while (IMU.available())
  {
    IMU.read();
  }
}


// ====================================================
// HEX 打印
// ====================================================
void printHex(const uint8_t *data, int len)
{
  for (int i = 0; i < len; i++)
  {
    if (data[i] < 0x10)
      Serial.print("0");

    Serial.print(data[i], HEX);
    Serial.print(" ");
  }

  Serial.println();
}


// ====================================================
// ASCII 指令
// ====================================================
void sendASCII(const char *cmd)
{
  clearIMU();

  Serial.print("ASCII TX -> ");
  Serial.println(cmd);

  IMU.print(cmd);
  IMU.print("\r\n");

  IMU.flush();

  delay(300);

  Serial.print("ASCII RX <- ");

  unsigned long start = millis();

  while (millis() - start < 700)
  {
    while (IMU.available())
    {
      uint8_t c = IMU.read();

      if (c == '\r' || c == '\n')
      {
        Serial.write(c);
      }
      else if (c >= 32 && c <= 126)
      {
        Serial.write(c);
      }
      else
      {
        Serial.print("[");

        if (c < 0x10)
          Serial.print("0");

        Serial.print(c, HEX);

        Serial.print("]");
      }
    }
  }

  Serial.println();
}


// ====================================================
// 修改 0x50 → 0x51
// ====================================================
void changeID()
{
  uint8_t cmd[8];

  cmd[0] = OLD_ID;

  // Modbus 写单寄存器
  cmd[1] = 0x06;

  // ID 寄存器 0x0005
  cmd[2] = 0x00;
  cmd[3] = 0x05;

  // 新 ID = 0x51
  cmd[4] = 0x00;
  cmd[5] = NEW_ID;

  uint16_t crc =
    modbusCRC(cmd, 6);

  // CRC 低字节先发
  cmd[6] = crc & 0xFF;
  cmd[7] = crc >> 8;


  Serial.println();
  Serial.println(
    "===== CHANGE ID ====="
  );

  Serial.print(
    "0x"
  );

  Serial.print(
    OLD_ID,
    HEX
  );

  Serial.print(
    " -> 0x"
  );

  Serial.println(
    NEW_ID,
    HEX
  );


  Serial.print(
    "TX -> "
  );

  printHex(
    cmd,
    8
  );


  clearIMU();

  IMU.write(
    cmd,
    8
  );

  IMU.flush();


  // 等回应
  delay(500);


  Serial.print(
    "RX <- "
  );


  if (!IMU.available())
  {
    Serial.println(
      "NO RESPONSE"
    );

    return;
  }


  while (IMU.available())
  {
    uint8_t b =
      IMU.read();

    if (b < 0x10)
      Serial.print("0");

    Serial.print(
      b,
      HEX
    );

    Serial.print(" ");
  }

  Serial.println();
}


// ====================================================
// SETUP
// ====================================================
void setup()
{
  Serial.begin(
    115200
  );

  delay(1000);


  Serial.println();
  Serial.println(
    "================================"
  );

  Serial.println(
    "IMU761 ID CONFIG"
  );

  Serial.println(
    "================================"
  );


  // ==================================================
  // 打开 GPIO42
  // ==================================================
  pinMode(
    IMU_POWER,
    OUTPUT
  );

  // GPIO42 LOW = IMU POWER ON
  digitalWrite(
    IMU_POWER,
    LOW
  );


  Serial.println(
    "GPIO42 = LOW"
  );

  Serial.println(
    "IMU POWER = ON"
  );


  // 等 IMU 上电
  delay(1500);


  // ==================================================
  // UART1
  // ==================================================
  IMU.begin(
    IMU_BAUD,
    SERIAL_8N1,
    IMU_RX,
    IMU_TX
  );


  Serial.println();

  Serial.println(
    "UART1 -> TX GPIO17 / RX GPIO18"
  );

  Serial.println(
    "Baudrate = 115200"
  );


  Serial.println();
  Serial.println(
    "IMPORTANT:"
  );

  Serial.println(
    "Hold IMU1 NRST LOW!"
  );

  Serial.println(
    "Only IMU2 should be running."
  );

  Serial.println();

  Serial.println(
    "Type G in Serial Monitor to start."
  );
}


// ====================================================
// LOOP
// ====================================================
void loop()
{
  if (Serial.available())
  {
    char c =
      Serial.read();


    if (
      c == 'G' ||
      c == 'g'
    )
    {
      Serial.println();
      Serial.println(
        "Starting..."
      );


      // ==============================================
      // 先关闭 IMU2 的自动数据输出
      // ==============================================
      sendASCII(
        "LOG DISABLE"
      );


      delay(500);


      // ==============================================
      // 修改地址
      // ==============================================
      changeID();


      delay(500);


      // ==============================================
      // 保存配置
      // ==============================================
      sendASCII(
        "SAVECONFIG"
      );


      delay(500);


      // ==============================================
      // 查询配置
      // ==============================================
      sendASCII(
        "LOG USRCONFIG"
      );


      Serial.println();
      Serial.println(
        "================================"
      );

      Serial.println(
        "Finished."
      );

      Serial.println(
        "Look for:"
      );

      Serial.println(
        "MODBUS_ID=0x51"
      );

      Serial.println(
        "================================"
      );
    }
  }
}
```

### 4. 两个 IMU 共用一个 UART

目标结构：

```text
一个 UART
   │
   ├── IMU1
   └── IMU2
```

更理想的逻辑结构：

```text
IMU1 → ID 0x50
IMU2 → ID 0x51
```

但是这里存在两个不同层面的问题。

#### 协议层问题

两个设备如果都是：

```text
MODBUS_ID=0x50
```

那么发送给 `0x50` 的命令时，两颗都会认为命令是发给自己的。

因此不能仅靠相同地址区分设备。

#### 电气层问题

普通 TTL UART TX 通常是推挽输出。

空闲状态：

```text
TX = HIGH
```

发送 0：

```text
TX = LOW
```

如果：

```text
IMU1 TX ───┐
           ├── ESP32 RX
IMU2 TX ───┘
```

可能出现：

```text
IMU1 TX = HIGH
IMU2 TX = LOW
```

此时两个输出会互相冲突。

因此：

> 改不同 ID 只能解决“谁应该回答”的协议问题，并不一定解决 TX 输出直接并联的电气问题。

---

#### `MODBUS_ID`

查询：

```text
LOG USRCONFIG
```

可以看到：

```text
MODBUS_ID=0x50
```

当前实验中两颗设备默认均为：

```text
0x50
```

曾尝试借鉴其他同类设备协议发送：

```text
50 06 00 05 00 51 55 B6
```

含义原本假设为：

```text
当前 ID：0x50
功能码：0x06
寄存器：0x0005
新 ID ：0x51
```

实际结果：

```text
RX <- NO RESPONSE
```

随后执行：

```text
LOG USRCONFIG
```

仍返回：

```text
MODBUS_ID=0x50
```

因此结论是：

> 当前 IMU761 的 TTL UART 上，不能把该 Modbus 写寄存器命令视为已验证可用方案。

不要因为发送的数据中出现 `0x51` 就认为修改成功。

判断是否真正成功的依据应是：

```text
LOG USRCONFIG
↓
MODBUS_ID=0x51
```

---

#### 使用 NRST 隔离两个 IMU

IMU761 提供：

```text
NRST
```

功能：

```text
NRST = LOW → 模块复位
```

因此可以：

```text
           UART
            │
      ┌─────┴─────┐
     IMU1         IMU2
      │            │
    NRST1        NRST2
```

当：

```text
IMU1 NRST = LOW
```

时：

```text
IMU1 → 复位
IMU2 → 正常运行
```

本次实验证明：

```text
LOG DISABLE   → OK
SAVECONFIG    → OK
LOG USRCONFIG → 正常返回
```

说明 NRST 隔离后，剩余单个 IMU 可以正常 UART 通信。

---

#### `SYNC_IN` 的作用

IMU761 提供：

```text
SYNC_IN
```

可以配合：

```text
LOG HI91 ONMARK 1
```

工作。

原理：

```text
SYNC_IN 上升沿
       ↓
IMU 输出一帧 HI91
```

这对于多 IMU 同步采样非常有价值。

例如：

```text
GPIO_A → IMU1 SYNC_IN
GPIO_B → IMU2 SYNC_IN
```

主控可以：

```text
触发 IMU1
↓
读取一帧

触发 IMU2
↓
读取一帧
```

但仍要注意：

> 如果两个 TXD1 被直接并联，必须确认未发送数据的一颗 TX 是否会释放总线，否则仍可能发生电气冲突。

---

### 5. 下一步尝试使用 SWD 强制修改配置

IMU761 还有：

```text
SWDIO
SWCLK
NRST
```

理论上可以通过 ST-LINK / J-Link 连接：

```text
ST-LINK SWDIO → IMU SWDIO
ST-LINK SWCLK → IMU SWCLK
ST-LINK NRST  → IMU NRST
ST-LINK GND   → IMU GND
ST-LINK Vref  → 3.3V
```

然后尝试：

```text
读取 MCU
↓
备份 Flash
↓
定位配置区
↓
查找 MODBUS_ID
↓
修改配置
```

但不能直接执行“找到所有 `0x50` 全部改成 `0x51`”。

因为 `0x50` 可能同时出现在程序代码、常量和配置数据里，而且配置区还可能带 CRC、Checksum 或版本信息。

正确顺序应该是：

```text
先读取
↓
先备份
↓
确认 MCU
↓
确认读保护
↓
分析配置区
↓
最后才写
```

### 6.排查顺序

以后遇到类似 UART 传感器问题，可以按下面顺序排查：

UART

```text
点对点串行通信
TX 和 RX 分开
普通 UART 没有天然的多机仲裁能力
```

TTL UART

```text
高低电平直接代表逻辑 1 / 0
一般为推挽输出
多个 TX 不能随意硬并联
```

帧头

```text
5A A5
```

用于从连续字节流中找到一帧数据的起始位置。

Payload

真正的传感器数据区域。

CRC

用于检查一帧数据在传输过程中有没有发生错误。

ID

用于区分总线上的不同设备，但：

```text
ID ≠ 自动解决物理电气冲突
```

NRST

```text
LOW → 复位
```

可以用于临时隔离某一个设备。

SYNC_IN

通过外部触发让 IMU 在指定时刻输出数据。

SWD

芯片级调试接口，可用于调试、烧录、读 Flash 和查看 MCU 状态，但直接修改 Flash 前必须先备份并确认配置结构。
