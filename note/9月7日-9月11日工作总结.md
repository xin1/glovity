### 2. 成功与失败原因

**结论：样本较多且分布均匀，结果稳定性较好。**

如果方向重复或者中途受到磁场干扰，采集 80 秒可能比 25 秒更差。

**失败主要原因：磁场不稳定、磁性干扰（过于靠近电脑）**

失败其他原因：

| 检查项                          | 当前阈值       | 检查内容                                     | 常见失败原因                                                 |
| ------------------------------- | -------------- | -------------------------------------------- | ------------------------------------------------------------ |
| `enough_samples`                | ≥ 500 点       | 有效数据总量是否足够                         | 采集时间太短、串口丢包、CSV 格式不正确、存在大量无法解析的行 |
| `enough_inliers`                | 内点比例 ≥ 90% | 稳健拟合后，正常点是否占绝大多数             | 周围磁场变化、经过磁铁/电机/钢材、线缆摆动、传感器读数突变、移动范围太大 |
| `all_octants_covered`           | 8/8 个八分体   | 三维空间八个方向区域是否都采集到了           | 只绕 Z 轴水平旋转、没有翻转设备、某些正负轴组合没有到达      |
| `direction_coverage_reasonable` | 条件数 ≤ 10    | 数据在球面上的分布是否相对均匀               | 点集中在一圈、一个平面或少数方向；虽然可能碰到了八个区域，但各区域数量严重不均 |
| `radius_cv_below_5_percent`     | CV ≤ 5%        | 校准后球面“厚不厚”，半径标准差÷平均半径      | 磁场不稳定、磁性干扰、软硬铁模型不能解释数据、异常点较多、采集位置发生移动 |
| `p95_error_below_10_percent`    | P95 ≤ 10%      | 95% 的内点，其半径误差是否小于目标半径的 10% | 局部方向误差大、存在成段干扰、球面出现凸起/凹陷、仍有较多异常点未被剔除 |
| `matrix_condition_below_5`      | 条件数 ≤ 5     | 校准矩阵最大与最小缩放比例是否合理           | 方向覆盖不足导致拟合退化、数据近似共面、某一轴范围太小；也可能是设备附近存在非常严重的软铁干扰 |

可视化的核心好处是：把原本只能“凭感觉转动”的校准过程，变成可以实时观察和有针对性补采的过程。

主要作用包括：

- 判断方向是否覆盖完整
  右侧红、黄、绿方向点可以直接显示哪些角度没有转到，避免只绕某一个轴旋转。
- 缩短采集时间
  不需要盲目采集固定的 60～120 秒。方向覆盖充分后就可以结束，有时约 20～30 秒也能获得合格结果。
- 提高校准成功率
  可以及时补充缺失方向，降低八分体覆盖不足、方向分布不均和矩阵条件数过大的概率。
- 及时发现磁场干扰
  左侧原始散点如果突然出现向外延伸的长线、孤立点或整体膨胀，通常说明设备靠近了电脑、金属、电机或其他磁性物体。
- 判断动作是否有效
  如果持续转动，但右侧仍有大量红点，说明动作可能集中在同一平面，需要增加翻滚和俯仰方向。
- 便于解释失败原因
  最终交互式 HTML 可以对比校准前后的点云：正常情况下，原始椭球经过校准后应变成以原点为中心、半径较一致的球面。

### 3. 什么会让原校准失效

只要以下任一条件改变，原矩阵就可能马上不再适用：

- PCB、传感器、螺丝、电池或外壳位置改变。
- USB线、电源线或大电流导线相对磁力计的位置改变。
- 电机、继电器、无线模块等工作状态改变。
- 设备靠近电脑、钢架、音箱、磁铁或其他磁性物体。
- 设备受到撞击，附近材料被重新磁化。
- 温度变化导致传感器零偏或灵敏度变化。
- 更换另一颗看似相同的 AK8963。

椭球校准本质上假设硬铁偏置和软铁矩阵是固定的线性参数；NXP 的校准说明也是以固定椭球模型描述 PCB 上硬铁、软铁影响。[NXP AN4246](https://www.nxp.com/docs/en/application-note/AN4246.pdf)

**数据质量会不会影响“持续正常时间”**

严格来说，不会影响硬件本身的漂移速度，但会影响初始校准误差和你还能容忍多少后续变化。

| 因素               | 对当前精度的影响               | 对持续时间的影响                       |
| ------------------ | ------------------------------ | -------------------------------------- |
| 样本数量           | 数量适当增加可降低随机误差     | 不会让传感器老化得更慢                 |
| 单点精度           | 噪声越小，参数估计越稳定       | 初始余量更大，因此可能更晚超过失效阈值 |
| 方向均匀程度       | 非常重要，决定矩阵能否可靠估计 | 覆盖不好时可能从一开始就不准           |
| 采集环境稳定性     | 极其重要，磁场变化会污染模型   | 污染后的参数可能换一个环境立即失效     |
| 重复方向上的大量点 | 收益很小                       | 基本不能延长有效时间                   |

对于你当前约 100 Hz 的采样率：

- 500 点是最低质量门槛。
- 1000～3000 个均匀点通常已经够用。
- 8000 个重复方向的点，不一定比 2000 个均匀点更好。
- 采集越久，接触磁场干扰的机会反而可能增加。

研究也表明，覆盖的椭球范围越完整，拟合对噪声越不敏感；只有一小部分椭球时，即使噪声很小，参数也容易不稳定。[Stanford 磁力计校准论文](https://web.stanford.edu/group/scpnt/gpslab/pubs/papers/Gebre_ICINS_2001_ins201.pdf)

## 三、维特IMU磁力计校准数据测试

完成了以下设备测试：

- Arduino通过I²C读取加速度、角速度、磁场和姿态角
- 传感器输出速率设置为`100 Hz`
- PC串口使用`115200 baud`

维特官方磁力计校准

开始校准：

```
WitStartMagCali();
```

其内部操作是：

```
解锁寄存器
→ CALSW写入0x07（CALMAGMM）
→ JY901P内部执行维特磁场校准算法
```

结束校准：

```
WitStopMagCali();
```

串口命令对应关系：

- `m`：调用`WitStartMagCali()`
- `e`：调用`WitStopMagCali()`
- `r`：重新设置并验证100 Hz
- `h`：显示帮助

`cal=1`只是Arduino本地状态；读取到：

```
CALSW=7
```

才可以确认JY901P确实进入了官方磁力计校准模式。

测试中发现，发送`m`后，磁场、姿态和陀螺数据可能在前一段时间保持不变。

维特售后解释为：

- 内部磁场算法需要积累最低数据量
- 达到所需数据量后才刷新或进行校准解算
- 这是传感器内部固件行为，不是Arduino采样率不足

**将传感器和Arduino轮询提高到100 Hz后，仍可能出现这一现象，因此不能完全依靠提高采样率消除。**

维特提供了两条查询指令：

```
FF AA 27 8F 00    查询校准进度
FF AA 27 A7 00    查询校准质量
```

进度定义：

```
返回0x01 → 25%
返回0x03 → 50%
返回0x07 → 75%
返回0x0F → 90%，开始质量解算
```

质量值除以100得到百分比，维特建议质量达到99%以上。

但这两条指令属于维特UART读取协议。当前使用I²C连接时，直接读取`0x8F`和`0xA7`始终返回：

```
progress_raw=0x0
quality=UNAVAILABLE
```

因此目前结论是：

- I²C下无法按现有方法获得真实进度和质量
- `progress_raw=0`不能解释为校准没有进展
- 需要维特进一步提供I²C模式下读取`0x8F/0xA7`的具体方法

## 四、瑞芬IMU761固件烧录

可以按下面流程升级。核心顺序是：设备断电 → 打开串口 → 选固件 → 点 Write → 再给 IMU 上电。

![image-20260917100859926](C:\Users\xinye\AppData\Roaming\Typora\typora-user-images\image-20260917100859926.png)

### 1. 接线与准备

使用 USB 转 TTL 串口模块，逻辑电平必须是 3.3V TTL，不能使用传统 ±RS-232 电平转换器。

断电状态下连接：

| IMU761 引脚   | 连接                 |
| ------------- | -------------------- |
| GND           | USB-TTL 的 GND       |
| RXD1（引脚4） | USB-TTL 的 TXD       |
| TXD1（引脚5） | USB-TTL 的 RXD       |
| VIN（引脚2）  | 稳定的 2.8–5.5V 电源 |

电脑目前能看到 `COM3、COM4、COM6、COM10、COM11`，但无法判断哪个是转换器。可以拔下 USB-TTL、重新插入，对比消失/新增的 COM 号。

资料确认 IMU761 默认 UART 波特率为 115200，接口定义也是上述接法：IMU761 惯性测量传感器模块.pdf；CAN2.0B 版补充资料见 IMU761 惯性测量传感器模块(2).pdf。

### 2. 实际升级步骤

1. 先让 IMU761 保持断电。

2. 关闭串口助手、ROS 节点等可能占用该 COM 口的软件。

3. 运行：
   [IMU500H_H5_ Bootloader V1_00.exe](D:/Desktop/github/glovity/code/IMU761/IMU500H_H5_ Bootloader V1_00/IMU500H_H5_ Bootloader V1_00.exe)

4. 在右上角设置：

   - `Serial Ports`：选择 USB-TTL 对应的 COM 口。
   - `Baudrate`：选择 `115200`。
   - 点击 `OPEN`。

5. 在 `Address` 中输入 `0`，然后点 `SET`。

   这里是截图所说的“68协议传感器地址”，默认值为 0，不是 CAN 节点地址。如果以前修改过该地址，应填写修改后的值。

6. 点击 `Open bin File`，选择：
   [IMU761_IIM_CAN2_0B_Common_V1_13.bin](D:/Desktop/github/glovity/code/IMU761/IMU761_IIM_CAN2_0B_Common_V1_13.bin)

   正确载入后，日志窗口应该显示固件的 sector 数量。该文件大小为 `245,588` 字节，SHA-256 为：

   `5D3D38FA288FA4C0FED56DCC09098D755E38A9C6666A2DD7914CB4C0A2A31AAC`

7. 确认 IMU 仍处于断电状态，然后点击 `Write bin File`。

8. 软件进入等待烧写状态后，再打开 IMU761 电源。Bootloader 会利用上电时机连接并开始烧写。

9. 烧写过程中不要：

   - 关闭软件；
   - 拔 USB-TTL；
   - 断开 GND；
   - 切断电源；
   - 点击其他按钮。

10. 等日志明确显示烧写完成/成功。如果出现 `End` 按钮，点击 `End`；随后关闭串口，将 IMU 断电数秒并重新上电。

### 3. 升级后检查

- 通过 UART 115200 发送 `LOGVERSION\r\n`，确认版本为 V1.13 或厂商对应的新版本。
- 检查 CAN 输出、节点地址、CAN 波特率和输出内容是否仍符合项目配置。
- 这份资料对 CAN 默认值存在不一致：不同位置分别写了默认 500 kbps/250 kbps以及不同节点地址。因此升级后不要仅凭“默认值”配置接收端，最好先保存原配置，或向瑞芬技术确认 V1.13 的实际默认 CAN 参数。

工具名虽然是 `IMU500H_H5 Bootloader`，但既然它和该 IMU761 固件由技术人员配套提供，可以使用；不要换刷目录中的其他 `.bin` 文件。若上电后一直没有开始烧写，优先检查 COM 口、TX/RX 是否交叉、公共 GND、115200 波特率以及 Address 是否确实为 0。

```

X = 1203.228571 LSB
Y = -11194.440476 LSB
Z = -53.033333 LSB

每轴灵敏度：
X = 8068.628571 LSB/g
Y = 8088.726190 LSB/g
Z = 8215.633333 LSB/g

程序不再简单执行`raw / 8192`，而是执行：

```
校准值 = (原始值 - 零偏) / 对应轴灵敏度

- 启动前三秒的静止校准；

## 六、LRA振动马达

### 1. 系统目标

使用LRA线性振动马达，根据压力大小、按压时间、不同纹理下产生五种触觉反馈：

- 脉冲：短促点击感
- 长振：持续按压感
- 锯齿：三层变化
- 摩擦：随压力变化而变化
- 碰撞：达到较大压力后产生清脆冲击感

系统支持网页可视化控制、参数编辑、F0检测、串口通信和立即停止。

### 2. 力阈值与震感对应

建议有效压力范围设为 `0～10N`：

| 压力范围  | 判断条件                 | 震感   | 默认参数                 |
| --------- | ------------------------ | ------ | ------------------------ |
| 0～0.2N   | 任意时长                 | 不触发 | 设置为接触死区，过滤噪声 |
| 0.3～1.9N | 按压不足500ms后松开      | 脉冲   | 150Hz、60ms、AMP 38      |
| 0.3～1.9N | 持续按压达到500ms        | 长振   | 130Hz、最短3秒、AMP 25   |
| 2.0～3.9N | 达到该区间               | 锯齿   | 170Hz、五级渐强、重复    |
| 4.0～5.9N | 持续按压                 | 摩擦   | 50～170Hz、最大AMP 35    |
| ≥6.0N     | 压力从低于6N跨越到6N以上 | 碰撞   | 170Hz、28ms、AMP 33      |

短振和长振共用同一个压力区间，通过按压时间区分，因此仍然能够得到五种不同触觉。

为防止压力在临界值附近反复切换，建议增加 `±0.2N` 回差。例如进入碰撞需要达到6.0N，退出碰撞区域需要下降到5.8N以下。

### 3. 硬件连接

```
Arduino D10 ← LRA TX
Arduino D11 → LRA RX（需要5V转3.3V分压/电平转换）
Arduino D6  → LRA IO1
Arduino GND ↔ LRA GND
外部5V/1A  → LRA VIN
马达       → LRA+、LRA-
```

Arduino USB串口为 `115200 baud`，Arduino与LRA模块之间为 `9600 baud`。

**Bambu Studio常用参数**

**支撑**

优先调整模型方向，减少支撑。

建议起点：

- Support：仅在需要时开启
- Support on build plate only：能用则开启
- Threshold Angle：约45°～55°
- Tree Support：适合不规则曲面
- Normal Support：适合规则平面和盒体

**常见问题排查**

| 问题         | 可能原因               | 调整方向                    |
| ------------ | ---------------------- | --------------------------- |
| 孔比设计值小 | 挤出线向内扩张         | 增加孔径或使用孔补偿        |
