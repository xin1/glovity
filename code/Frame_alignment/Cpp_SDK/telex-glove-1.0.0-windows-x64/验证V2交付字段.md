# Windows C++ SDK：V2 交付字段验证

`glovity_v2_monitor` 不修改固件，直接解析固件已经输出的 180 字节 V2 帧，并使用
`telex_glove.dll` 计算 21 个关节。它显示以下交付字段：

- `protocol=v2-180`、左右手、电量；
- `frame_seq`、设备 `timestamp_us` 和主机单调接收时间；
- `recording`、`imu_fail_mask`；
- `wrist_gyro_valid`、`wrist_gyro_dps`；
- IMU 正常时的食指尖关节；任一 IMU 失败时明确显示 `joints=N/A`。

## 1. 编译

在“x64 Native Tools Command Prompt for VS”中进入 SDK 根目录：

```powershell
cmake -S share\telex-glove\examples -B build-examples -A x64 `
  -DCMAKE_PREFIX_PATH="$PWD"
cmake --build build-examples --config Release
Copy-Item bin\telex_glove.dll build-examples\Release\
```

必须使用 x64。SDK 附带的 `.lib` 是 MSVC 导入库，建议使用 Visual Studio 2022。

## 2. 文件回放验证

```powershell
.\build-examples\Release\glovity_v2_monitor.exe `
  file://D:\path\to\v2_capture.bin
```

正常结果应逐帧出现 `protocol=v2-180`，结束统计的 `valid` 大于 0、进程退出码为 0。
如果输入是原包的 168 字节 `sample_capture.bin`，`valid=0` 是预期结果，因为它不是 V2
交付格式。

## 3. 真机验证

关闭串口助手及原来的 `monitor_hands.exe`，保证只有一个程序读取串口：

```powershell
.\build-examples\Release\glovity_v2_monitor.exe COM3 2000000
```

如设备使用 921600 波特率，把最后一个参数改成 `921600`。按 Ctrl+C 结束。

验收时依次检查：

1. 左右手分别显示为 `left`、`right`，电量在 0–100；
2. `frame_seq` 连续递增，允许丢包及从 65535 回绕到 0；
3. `timestamp_us` 连续增长，设备重启后允许重新起算；
4. REC 拉高/拉低后，后续帧的 `recording` 分别变为 1/0；
5. 正常状态 `fail_mask=0x000`；模拟单路 IMU 故障时相应位变为 1，且关节显示 N/A；
6. 腕部角速度有效时 `gyro_valid=1` 并显示三个 dps 数值；
7. Ctrl+C 后 `valid` 大于 0，`rejected_candidates` 不应持续快速增长。

## 4. 当前边界

原始 `telex_glove.dll` ABI 1 的 `telex_glove_snapshot` 没有 REC、设备时间和失败掩码字段，
且当前文件夹没有 DLL 源码，因此这些字段由新增的公开头文件 `include/glovity_frame_v2.hpp`
解析。现有 DLL 只负责 FK 关节计算。若必须让 `telex::GloveHub` 的 `Snapshot` 本身直接包含
这些字段，需要取得 DLL 源码后发布 ABI 2；仅修改头文件不能改变已有 DLL 的内部输出。
