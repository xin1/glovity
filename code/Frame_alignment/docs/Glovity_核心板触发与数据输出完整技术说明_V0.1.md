## 3 硬件修改与电气责任

| 端点 | 修改及保持内容 |
| --- | --- |
| U6 1脚 | 保留IR受控3.3V支路，定义为3V3_REF；不作为基站电源。 |
| U6 2脚 | 仅断开此接口SCL支路，改接GPIO4，网络名OUTPUT_EN。 |
| U6 3脚 | 仅断开此接口SDA支路，改接GPIO5，网络名REC_IN。 |
| U6 4脚 | GND保持并实际共地。 |
| GPIO8/9 | 保留全体IMU和其他所需接口的I²C总线，不能全网重命名或切断。 |
| GPIO6 | 仅在实现本地短按功能时接新增KEY_SENSE支路。 |

OUTPUT_EN约10kΩ上拉到主板受控+3.3V；REC约10kΩ下拉到地。信号支路建议串100–330Ω并配适当ESD保护，实际阻值、缓冲器和保护器件由线缆与信号边沿验证决定。小串阻不等同于5V电平转换或断电隔离。

NOKOV侧OUTPUT_EN优先开漏，释放表示允许；REC优先3.3V推挽或经双方确认的等效电路。高阻不等于高电平：REC的高阻将被本板下拉为低。输出高/低应留门限裕量，芯片3.3V时VIH参考2.475V、VIL参考0.825V。

当手套主电源为零但基站仍工作，REC高电平可能经GPIO保护结构倒灌。应采用断电高阻驱动或具有断电保护的缓冲方案；量测关机电流和管脚电压。若用参考脚感知供电，不能把IR关闭等同于主控关机，亦不能把IR有电当成固件已就绪。

双手接同一基站时，各3V3_REF不得并联。每只手建议独立OUTPUT_EN拉低通道，避免一根高电平线把两只手的上拉电源耦合；若共用控制节点，须验证单侧关机倒灌。公共逻辑命令可以相同，但电气隔离和电平参考仍按每只手独立设计。

线束最终必须有Pin 1方向图、插座和端子料号、线色映射、是否交叉说明。不能仅凭SH1.0 4P名称确定插头观察方向或针序。

## 4 REC状态机与按键仲裁

外部模式下REC为电平状态，不是上升沿切换命令。双边沿中断记录事件和本地时间，采集开始处取得一致快照，生成recording位。中断不读I²C、不打印、不写文件、不直接发包。

| 情况 | 处理规则 |
| --- | --- |
| 启动时REC已高 | 初始化实际电平，首帧录制位为1；事件历史未知，不伪造早于启动的边沿。 |
| 读取中途边沿 | 当前帧保持原状态，后续新读取帧使用新状态。 |
| 短暂高脉冲 | 可能没有任何普通帧显示为1；如业务需要捕获，采用独立事件队列而非扩展普通帧。 |
| OUTPUT_EN低期间变化 | 内部继续跟踪REC；恢复时使用当时状态，不生成虚假的重新开始事件。 |
| 拔线 | REC下拉为0；无法分辨人为停止和断线。 |
| 同时边沿 | REC归属按一致快照确定；OUTPUT_EN在提交发送前另做有效性检查，避免读取期间拉低后仍提交。 |

### 本地短按模式

外部模式跟随REC，本地模式才允许短按切换录制。不能因REC低而自动进入本地模式；OUTPUT_EN在两种模式下均有效。对NOKOV集成默认外部模式。模式配置途径与确认响应需正式定义，不能隐式切换。

原U8为UOV-K20，KEY属于电池域；GPIO41/Q4是软件关机输出，不可当按键输入。既有方案新增AO3400或AO3400A：KEY_RAW经10kΩ接G，S接GND，D接GPIO6并经10kΩ上拉至主板受控3.3V。按下GPIO6高、释放低；实际KEY电压与最低电池电压下导通需验证。

软件需开机等待释放，20–30ms消抖，在松手时判断短按，例如50–500ms；窗口必须低于实装UOV长按关机阈值，不能把型号名直接当固定时长。软件主动关机时屏蔽按键事件。Q5支路不得照搬Q4的栅极下拉而加载原KEY节点。

## 5 输出使能与异常边界

OUTPUT_EN只门控普通IMU数据。低电平期间继续读取、计时、跟踪REC及递增采集帧号，丢弃本应发送的普通帧；不建立历史补发仓库。恢复后等待下一轮新采集。

在禁止边沿时增加内部输出代次并清理未提交普通帧；发送任务检查代次和当前使能，防止“低后又高”期间旧队列帧漏出。采集快照与最终发送许可是两个不同检查点。已进入驱动、无线在途或接收器下游队列的帧不可保证撤销。

若需要限制接收器尾流，可新增带序号的管理状态通知及清队列策略，但不能承诺无线通知瞬时可靠。必须用示波器或逻辑分析与接收记录测定实际尾流，当前无确定微秒或帧数上限。

### 禁止输出时的在线状态

good接收器当前依靠收到普通帧更新状态，长期停发会被误判离线。需用低频状态消息区分在线且停发、校准中、正常输出及真正失联。心跳周期和超时应匹配；原接收器存在约1秒状态超时，不能直接使用恰好1Hz且无裕量的心跳。

### 校准与普通流

当前good校准模式会停止普通数据。建议录制中拒绝进入校准；校准中收到REC高时保留输入状态并返回未就绪状态，不承诺此时已有普通数据。校准完成恢复正常读取时，再按REC实际状态标记。本机低电量关机、硬件掉电及总线故障优先于持续输出要求。

“超时不干扰输出”应解释为不追加阻塞重试和诊断开销；真实传感器失败或物理链路中断仍会产生无效帧或缺帧。异常不能通过重复旧数据并标记有效来掩盖。

## 6 计时实现与对齐边界

timestamp_us表示手套在本轮开始读取数据时的本地计时值。它不是数据包到达基站的时间，不是UTC，也不是外部设备的同步时间。时间戳在采集端写入，经过无线、接收器和USB时保持不变。

| 操作或情形 | 时间戳行为 |
| --- | --- |
| 正常连续采集 | 连续增长；相邻时间戳之差反映读取开始间隔。 |
| REC拉高或拉低 | 不清零、不暂停。 |
| OUTPUT_EN拉低再恢复 | 禁止期间继续计时，恢复后时间戳自然跳过这段时间。 |
| 设备重启或重新上电 | 本地计时重新起算；需建立新的数据会话。 |
| 左右手同时工作 | 各自独立起点与时钟，不能直接相减作为同步误差。 |

64位无符号微秒字段的表示范围约58.5万年，足以覆盖正常会话；底层计时实现仍以实际固件为准。微秒单位仅表示数值分辨率，不代表IMU有效采样时间、触发响应或跨设备对齐精度达到1µs。

实现可使用esp_timer_get_time()，在采集开始时读取并保存至uint64字段。底层API通常返回int64微秒值，正常非负区间可编码为uint64；字段的58.5万年容量不是底层硬件或API寿命保证。无需重置系统计时器，也不应改变good依赖micros()/millis()的调度及超时基准。

时间戳、REC状态和帧号必须形成一致快照。ESP32-S3为32位处理器，共享64位数据不能仅靠volatile保证原子性。通过短临界区、明确所有权或队列传递保证一致性；临界区内不得包含I²C或发送。中断延迟存在，不能将软件边沿时间宣传为无误差的物理边沿捕获。

跨设备需要偏移与频率映射t_ref≈a×t_local+b。当前两根线都无同步含义，不存在可以合法推出a、b的对时协议。首个REC帧对齐仅为粗分段；任意40ppm相对频偏的示例在600秒可积累24ms误差，该数值不是本板实测。

## 7 新版180字节普通帧

普通IMU数据包固定180字节，一包对应一只手。多字节整数为小端序，int16为有符号二进制补码；无填充字节、无换行符。无线应用载荷与有线数据帧逐字节一致。

| 偏移 | 字段 | 字节 | 定义 |
| --- | --- | --- | --- |
| 0–1 | magic | 2 | AA 55，按字节排列 |
| 2 | version | 1 | 02，新版固定格式 |
| 3 | hand_id | 1 | 00左手，01右手 |
| 4 | flags | 1 | bit0录制；bit1手腕角速度有效；其余0 |
| 5 | battery_percent | 1 | 0–100，缓存电量，约1 Hz更新 |
| 6–7 | frame_seq | 2 | uint16，每轮开始读取递增，按65536循环 |
| 8–15 | timestamp_us | 8 | uint64，本轮读取开始时间，单位µs |
| 16–17 | imu_fail_mask | 2 | bit0–10为IMU失败位；bit11–15为0 |
| 18–171 | imu[11][7] | 154 | 77个int16，按IMU索引依次排列 |
| 172–177 | wrist_gyro[3] | 6 | 3个int16，依次Gx Gy Gz |
| 178–179 | crc16 | 2 | CRC覆盖字节0–177，低字节在前 |

该版本固定11组IMU数据，不另设数量和包长字段。旧版168字节USB帧与新版180字节包字段布局不兼容，但升级后的接收器和解析端必须通过长度、头部特征与校验方式明确识别两者，禁止按错误偏移解释。此表为本版拟实施定义，尚未作为已烧录固件通过联调验收。

此精简版用偏移18开始存IMU数据、偏移172开始存手腕角速度；CRC位于178。旧版168字节包的IMU偏移为7、角速度偏移161，不能沿用旧解码偏移。每个IMU连续14字节，索引i起始位置为18+14×i。

## 8 字段语义与解析约束

| 内容 | 排列与换算 |
| --- | --- |
| 单颗IMU的7个值 | Roll、Pitch、Yaw、Q0、Q1、Q2、Q3；Q0为标量分量，沿用现有SDK。 |
| 欧拉角 | 角度＝原始int16 ÷ 32768 × 180，单位°。 |
| 四元数 | 各分量＝原始int16 ÷ 32768；顺序为w x y z。 |
| 手腕角速度 | 角速度＝原始int16 ÷ 32768 × 2000，单位°/s。 |
| 索引与安装位置 | 索引0对应手腕参考模块；索引1–10的解剖位置、安装朝向及全局坐标变换由交付映射表另行确认。 |

失败掩码为1的IMU，其7个值置零且不得作为有效姿态使用；手腕角速度仅在flags bit1为1时有效，失败时置零。四元数符号q与−q可表示相同旋转，融合或插值前应处理符号连续性。上述换算沿用现有软件约定，不构成全局坐标系或安装标定的定义。

帧序号每次真正启动一轮读取递增，即使最终禁止输出或发送失败也不回退；只因调度逾期而未启动的周期不凭空生成帧号。由此，跳号可能来自主动停发、发送丢弃或链路丢包；长时间无数据和16位回绕后无法仅靠序号精确统计丢帧。

时间戳不包含boot_id；同一会话以时间和帧号识别重复，结合设备身份与连接会话去重。手套重启后第一帧时间未必恰好为0，因为初始化先消耗时间。解析端要区分乱序旧帧与重启，必要时重新查询设备状态。

CRC-16/CCITT-FALSE参数：poly=0x1021、init=0xFFFF、refin=false、refout=false、xorout=0x0000。覆盖完整前178字节，以小端写CRC。CRC用于传输校验，不是认证机制。解析器先检查帧头、版本、长度与CRC，再解释状态和数值。

USB按字节流处理，环形缓存上限明确。遇错误前移1字节重新寻头；正常载荷可能包含AA 55。普通帧没有msg_type，管理消息必须用另一个不冲突的帧头和明确长度/校验规则；本轮未冻结管理帧结构，不可自动认定good旧文本命令已经适配。

## 10 采集与电池的非阻塞设计

建议采集任务按固定期限启动一轮，准备帧头、缓存电量、序号、时间和REC快照，顺序读取各IMU并设置有效性，计算CRC后向独立USB/无线发送队列提交。采集任务不等待主机打开串口、不等待USB可写、不等待无线回调。

当前ReadOneImu对每颗分开读取欧拉角和四元数，手腕另读角速度。保留这些读取以保持输出含义，不把四元数推导欧拉角当成完全等价替代。这样可避免引入坐标顺序、量化和寄存器更新时间造成的变化。

### 电池更新

good CheckLowBattery本来约1Hz执行，但ReadBatteryVoltage(8)包含8次delay(2)，形成约16ms显式等待；BatteryPercent还在每帧另读一次ADC。新设计统一1Hz检测/更新缓存，可用单次采样加时间滤波或分散多次采样，不在采集路径连续等待。低电量阈值与持续时间保护应保留并回归验证。

### 超时与期限

每次I²C事务需设有限超时并测量实际执行上限。缺失地址、NACK与总线拉死分别处理；不在同一帧无限重试。失败姿态置零加掩码，手腕失败清valid位。维护阶段按退避策略重探测，避免每帧对失效设备重复长等待。

超过帧期限时记录overrun并跳过无法兑现的调度槽，恢复下一有效期限；不依靠紧密连发来追赶平均频率。若一次驱动调用本身超时，仍可能造成缺帧，必须如实统计。输出速率与采集周期在此版本保持一轮一包关系；不得重复旧数据构造“100Hz新数据”。

## 11 发送队列与背压

USB和无线分别持有有界待发队列，不能共享一个会互相阻塞的发送锁。无主机、串口读取慢、无线发送失败都不阻塞IMU读取。普通流采用实时优先策略：队列满时丢弃最旧的尚未提交完整帧，保留较新数据，分别统计每条链路的丢弃和失败。

USB若一帧已部分写入，需保持发送偏移并完成余下部分，不能在其中插入其他帧或文本。OUTPUT_EN禁止时可取消尚未开始的帧，但已经写入字节流的帧应完成，属于允许存在的尾流。管理消息按完整帧边界调度。

无线使用发送完成回调推进下一次提交，并检查esp_now_send返回值；回调只更新状态/通知任务，不承担采集和长耗时工作。普通实时帧不进行无界应用重传；重要控制/事件的确认与重传采用独立协议。MAC层发送成功不等同上位机已经保存。

### 接收器64帧队列建议

目标为64个可用帧槽，180×64=11,520字节纯载荷，另需元数据。若继续以head/tail相等代表空并保留空槽，则需65个槽才能得到64帧有效容量；或者改成计数方案。当前8槽实际7帧。

| 配置 | 双手30Hz | 双手100Hz |
| --- | --- | --- |
| 64帧有效容量 | 约1.07秒 | 约0.32秒 |
| 意义 | 吸收短时USB停顿 | 不保证持续无丢帧 |

缓冲时长也可能变为数据延迟，不能无条件扩大。建议同时统计队列峰值与最旧帧年龄；必要时用实时模式的年龄上限丢弃过期帧，具体阈值由业务验收确定。未验证前不将64帧视为已经实施配置。

## 12 帧率与带宽评估

| 项目 | 30Hz每只手 | 100Hz每只手 |
| --- | --- | --- |
| 帧周期 | 33.33ms | 10ms |
| I²C有效数据 | 4,800 B/s | 16,000 B/s |
| 400kHz纯时钟占用 | 15.46% | 51.53% |
| 单手180字节应用数据 | 5,400 B/s | 18,000 B/s |
| 双手应用数据 | 10,800 B/s | 36,000 B/s |
| 双手UART 8N1最低数据位率 | 108kbit/s | 360kbit/s |

每轮有效读取160字节，23次寄存器读，每次3字节地址/指针开销，合计(160+23×3)×9=2061个SCL时钟。400kHz纯时钟耗时5.1525ms；未含START/STOP、事务空隙、驱动、时钟拉伸及异常处理，因此不能由51.53%推出稳定100Hz。

180字节小于250字节兼容包长限制。双手100Hz应用载荷约288kbit/s，无线还需帧头、应答、竞争和重传。默认ESP-NOW 1Mbit/s不是应用吞吐保证，须测双手同时发送和干扰环境。真实UART建议921600或已验证更高速率；原生USB虚拟串口另测缓冲和主机读取。

历史30Hz测试在S3左手上记录60秒、1801条连续帧摘要、约30.00052Hz、失败掩码全0。该测试不是新180字节固件测试，未证明每次读数新鲜、手腕角速度全部成功或双手无线100Hz稳定。

文档统一表述：默认每只手30Hz，支持配置调整至最高100Hz目标；100Hz在修改调度、缓冲和超时后，按实装IMU更新能力及双手链路验证。当前无硬件实测结果时不将“可调整”写成已验收性能。

## 13 风险与可观测性

| 风险 | 措施与保留边界 |
| --- | --- |
| 高阻误认为高电平 | OUTPUT_EN上拉释放高；REC下拉需要主动高，双方电路确认。 |
| 参考电源并接或倒灌 | 每只手独立参考，禁止向参考脚供电；验证单方断电。 |
| 一帧跨越REC边沿 | 帧开始快照，下一帧生效；不宣称精确边沿采样。 |
| 时间被解释为全局同步 | 对外明确本地时间，无对时输入，无精度承诺。 |
| 帧序号跳变原因不明 | 内部区分停发、队列丢弃、无线失败、解析CRC错误，状态查询报告。 |
| 重启与乱序混淆 | 按连接会话与状态识别；精简包不带boot_id，不能只看一包时间倒退。 |
| 长停发误报离线 | 独立低频状态与有裕量超时。 |
| 采集100Hz但数据未更新 | 确认IMU配置，动态测有效更新；不以静态数值重复直接定论。 |
| 校准/电池阻塞 | 采集与维护隔离，电池缓存1Hz，校准与录制互斥。 |
| 队列扩大增加延迟 | 监测峰值和年龄，实时优先、有限缓冲。 |

建议维护计数：采集轮数、逾期轮数、读取耗时最大值和分位统计、各IMU失败数、手腕失败数、主动停发数、各链路队列丢弃、无线提交/回调失败、USB部分写入与断连、REC事件队列溢出。统计不得逐帧打印或在采集临界区汇总。
