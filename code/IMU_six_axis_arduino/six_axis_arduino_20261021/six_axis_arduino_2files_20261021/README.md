# 六轴验证固件：Arduino 两文件版（2026-10-21）

本包将 `05_six_axis_20261020` 的多头文件源码合并成每块板两个文件。协议、控制、采样和配对检查逻辑与该版一致。仅替换交付形式，不是另一套算法。

```text
GloveLeft/
  GloveLeft.ino
  GloveLeft.h
Receiver/
  Receiver.ino
  Receiver.h
```

## 交给烧录负责人的步骤

1. 解压后保留上述草图文件夹名；每个 `.ino` 和同名 `.h` 放在一起。两个草图各自独立，不依赖 `shared/`、Python 或另一个草图目录。
2. 当前离线烧录版不再把 MAC 写死在源码中。首次启动时固件通过串口接收对方的 STA MAC，并保存到 NVS；后续启动直接读取已保存的配对。配套 EXE 会自动完成清除旧配对、烧录和写入新配对。
3. Arduino IDE 使用 **esp32 by Espressif Systems 3.0.7**。选择实物开发板及原有 USB、Flash、PSRAM、分区等选项。原来若不是这个核心版本，需要安装此版本，不能只更换源码后沿用任意版本。
4. 打开 `GloveLeft/GloveLeft.ino`，选择左手主控板对应端口，点击验证、上传。
5. 打开 `Receiver/Receiver.ino`，选择接收器对应开发板和端口，点击验证、上传。
6. 返回最终两份头文件、实际开发板/核心版本/板选项和编译上传结果，供本机归档验证。

`.h` 是源码依赖，Arduino 编译时自动包含，不需要单独打开、编译或烧录。上传的是整份程序编译生成的固件；不是把 `.ino` 文本直接写入板子。

原始固件也是 `.ino` 包含 `.h` 后一起编译。现在恢复相同的文件组织方式，但新协议要求**左手和接收器都更新**。右手不更新。旧电脑可视化不能直接读取新协议。

## 这台电脑上的控制与验证

继续使用既有工具，不需要更换解析器：

```bash
~/venvs/telex/bin/python firmware/05_six_axis_20261020/tools/control.py --port /dev/ttyACM0
```

具体控制、九轴准备→六轴采集、磁校准和原始数据检查步骤见项目中的 `firmware/05_six_axis_20261020/README.md`。电脑端不需要本包里的 MAC 配置。

## 验证范围

本包两块草图分别检查了普通生产路径和编译检查路径：在相同条件下，与多文件版的 C++ 预处理输出去除空白行后逐字节一致；已消除所有工程内头文件引用，仅保留 Arduino/ESP32/标准库依赖。检查所用模拟 MAC 仅存在于临时副本，未写入交付。原版的控制/协议与电脑模拟串口集成测试本轮重新运行，4 项均通过。

多文件版此前已完成 Arduino-ESP32 3.0.7 的 ESP32-S3 编译。本轮环境未保留此前临时安装的 ESP32 工具链，因此两文件版本轮没有重新运行 ESP32 编译，也没有实物烧录；预处理等价检查不替代实际开发板编译和硬件验收。详细等价检查结果及源码哈希见 `validation.json`。

负责人不需要运行本项目的软件测试；在实际配置下执行 Arduino IDE 的验证和上传即可。
