# UNO 原始数据诊断版

打开同目录 .ino，开发板选择 Arduino Uno（经典 R3 / ATmega328P），上传；串口监视器选择 **9600、文本显示**。这是独立单文件程序，不需要 hi91.h。传感器也必须实际使用9600。

保持当前实验线路：公共接收线接 D10，D11 悬空，共地，各模块正常供电。使用二极管汇接时，每个 IMU TX 各一个二极管，阴极朝 IMU TX、阳极朝公共 RX，公共 RX 用4.7kΩ上拉到3.3V。不要把原来线路改成 TX 直接短接。

不接 SYNC_IN，不发送配置、改地址或未经确认的查询命令。支持现有新版 HI91 地址01/02。

程序采集约2秒，然后暂停软件串口接收，输出本窗口最初96个原始字节、CRC统计、地址01/02的有效帧数与最后一帧姿态，再开始下一窗口。统计每窗口清零。打印期间明确丢弃输入，本版仅用于诊断，不是连续无丢帧采集。窗口边缘截断、开始时处于一帧中间都可能引起 discard 增长，不能直接当成碰撞次数。

与旧版相比：采集过程中不打印，减少打印堵塞造成的软件缓冲溢出；显示原始 HEX，不再只能看到 discard 数字；USB 与传感器默认都为9600，启动提示显示实际常量。

判断：
- RAW 出现 5A A5 4C 00，valid增加：对应链路和解析正常。
- bytes增长、RAW始终无帧头：检查实际波特率、输入电平和混合发送。
- RAW有帧头、crc_bad增长：可能数据损坏或接收丢字节。
- bytes=0：没有数据输入，检查接线、供电及输出模式。

先可直接观察当前双机线路。若无有效帧，再分别断开另一只的信号线，比较单只01、单只02与双机结果。

若需要试传感器115200，仅修改 SENSOR_BAUD=115200，电脑仍选9600；UNO SoftwareSerial高速接收稳定性有限，结果不能替代USB-TTL硬件接收验证。

等待厂家提供地址查询协议后，才能增加正式轮询。本程序无法阻止两个自动输出设备同时发送。
