# IMU761 + Arduino UNO R3 双 IMU 测试

适用：经典 UNO R3 / ATmega328P、新版/Wearable HI91（地址位在整帧偏移 10）、地址 `0x01` 和 `0x02`。其他 UNO 型号需重新适配。

## 先读：当前三线接法还不能直接地址轮询

两个 IMU 的 TX 经二极管汇接、RX 共接、GND 共地，只解决物理连接。地址不同不会自动让它们轮流发送。当前资料没有确认该固件的“带目标地址读取一帧”命令，本程序不猜测该命令，也不会修改地址。

本程序默认采用手册明确的 ONMARK + SYNC_IN 方案。**必须额外把两个 SYNC_IN 分别连接至 UNO D6、D7，并逐只验证当前固件支持 ONMARK。** 如果目前不加触发线，使用下述单机被动诊断模式；不能把两只主动输出的 IMU 合到一起当作正常采集。

## 文件与软件设置

- `imu761_uno_test/imu761_uno_test.ino`：主程序。
- `imu761_uno_test/hi91.h`：CRC、流式解帧及地址/姿态解析，必须与 .ino 放在同一文件夹。
- Arduino IDE 选择 **Arduino AVR Boards → Arduino Uno**，选择 UNO 对应 COM 口。
- 仅依赖 AVR 核心自带的 SoftwareSerial，无需安装第三方库。
- USB 串口监视器：**115200**；IMU 软件串口：**9600、8N1**。两者不同是正常的。
- D0、D1 保留给 USB 调试，不接 IMU。

## 硬件接线

UNO 是 5 V 主控。以下按 IMU 侧 3.3 V 信号接线；避免依赖转接板或定制固件的 5 V 耐受性。

| UNO / 电源 | 连接 |
|---|---|
| D10 软件串口 RX | 两个二极管阳极汇合处，即公共 RX 总线 |
| D11 软件串口 TX | 经 1kΩ/2kΩ 分压后，接两只 IMU 的 RXD1（测试程序不发命令，此线可不接） |
| D6 | 经 1kΩ/2kΩ 分压后，接地址 01 的 SYNC_IN |
| D7 | 经 1kΩ/2kΩ 分压后，接地址 02 的 SYNC_IN |
| GND | IMU 01、IMU 02、外部电源 GND 全部共地 |
| 外部稳压 3.3 V | 两只裸模块 VIN；若是转接板，以转接板输入规格为准 |

二极管回传总线：

```text
                         稳压 3.3V
                             |
                            4.7kΩ
                             |
UNO D10 ---------------------+----- A--|>|--K ---- IMU 01 TXD1
                             |
                             +----- A--|>|--K ---- IMU 02 TXD1
```

- 每只 IMU 的 TX 支路各一个低压降肖特基二极管，例如 BAT54；先按器件封装资料识别 A/K。
- 阳极 A 朝公共 RX，阴极 K 朝各自 IMU TX；两个 TX 不可先短接再共用一个二极管。
- 外部上拉仅接 3.3 V，不能接 5 V。代码已关闭 SoftwareSerial 默认的 D10 内部上拉。
- 不发送时总线应接近 3.3 V。示波器可进一步确认低电平和边沿；万用表只能检查静态电压。

每个 UNO 输出分别分压，不要共用一组电阻：

```text
UNO D6/D7/D11 ---- 1kΩ ----+---- 对应 IMU 输入
                         |
                        2kΩ
                         |
                        GND
```

5 V 输出经该分压约为 3.33 V；2kΩ 同时为复位期间提供下拉。D11 如果不接，公共 IMU RXD1 可用 10kΩ 上拉到 3.3 V，保持串口空闲高电平。

两只 IMU 建议用独立、容量留有余量的稳压 3.3 V 电源（例如额定至少 300 mA），共地即可，不要将两个稳压器输出并联。**不要用 UNO 的 3.3 V 引脚承担两只 IMU 的供电**，UNO R3 官方规格该输出上限为 50 mA。每只模块附近建议放 0.1uF + 10uF 去耦。

裸模块手册引脚：RXD1=4，TXD1=5，SYNC_IN=6；转接板按丝印。这里使用的是 SYNC_IN，不是 SYNC_OUT，也不是 NRST。

## 一次性配置：用 USB-TTL 单独配置每只 IMU

已有地址 01、02 保留不变。配置时断开 UNO 以及另一只 IMU，防止串口输出争用。用支持发送 ASCII 命令的串口助手；地址配置 EXE 固定 115200，不能替代更改波特率后的串口助手。

1. 串口助手连接单只 IMU，选当前波特率（原配置通常是 115200），8N1。
2. ASCII 文本方式发送以下命令，每条结尾 CRLF（`\r\n`），每条观察响应再继续：

```text
LOG HI91 ONMARK 1
LOG ENABLE
SERIALCONFIG 9600
```

3. `SERIALCONFIG 9600` 立即改变波特率，立即把串口助手改为 **9600**，再发送：

```text
SAVECONFIG
REBOOT
```

4. 等待启动完成；用 `LOG COMCONFIG` 检查配置，然后等待文字应答结束。正常状态应在不触发时保持安静。
5. 通过一个单独 SYNC_IN 脉冲确认只输出一帧 82 字节 HI91，帧头 `5A A5 4C 00`。若固件不接受命令或未实现该行为，不要合并两只模块进行测试。
6. 另一只 IMU 重复操作，之后再按接线表连接两只。

不要在设置 9600 后仍保留原先 100 Hz 的自动输出：82 字节/帧在 9600 下约占 85.4 ms，带宽不够。ONMARK 模式由程序控制低速触发。

不要在公共串口发送 `LOG HI91 ONMARK ONCE`；该 ASCII 命令不带目标地址，可能使两只同时回复。不要以 `LOG DISABLE` 作为最终采集配置，它是全局禁用输出。

## 上传与运行

1. 保持 `.ino` 和 `hi91.h` 同目录，在 Arduino IDE 打开 .ino。
2. 默认 `#define TEST_MODE 1`，即双机 SYNC 模式。确认 D6、D7 和 ONMARK 均已准备好。
3. 选择 Arduino Uno 和端口，验证并上传。
4. 打开 115200 的串口监视器。UNO 复位后等待 6 秒，然后要求总线连续 1.2 秒无字节。
5. 以约 250 ms 的间隔交替触发 01、02，目标每只约 2 Hz；每秒打印统计与最近一帧姿态。

示意输出（数值仅为格式示例，不代表已实测）：

```text
Bus quiet. Starting alternating triggers.
bytes=328 crc=0 discard=0 overflow=0 timeout=0 unexpected=0
ID=01 frames=2 imu_ms=8100 roll=0.12 pitch=-0.30 yaw=1.20
ID=02 frames=2 imu_ms=8350 roll=0.20 pitch=0.10 yaw=-2.00
```

roll/pitch/yaw 单位为度。`imu_ms` 是各 IMU 上电以来的本地时间，两只的时间基准并未同步。旋转其中一只时，其对应 ID 的姿态应该改变。

- `frames`：CRC 正确且地址符合预期的累计帧数。
- `crc`：完整候选帧的 CRC 失败次数；不是所有丢帧的总数。
- `discard`：找帧头过程中丢弃的字节数。
- `overflow`：SoftwareSerial 软件缓冲溢出次数。
- `timeout`：触发后 250 ms 内未收到有效帧。
- `unexpected`：未触发却收到字节，或返回地址不符合预期。

发送 `s` 可停止触发；排除故障后按 UNO Reset 重启。异常会停止后续触发，不盲目跳到下一只，避免迟到帧串入下一轮。

## 尚未增加 SYNC_IN：只做单机诊断

把 `TEST_MODE` 改为 `0`。**仅连接一只 IMU，另一只的信号线也应断开，避免断电模块影响总线。** 单只通过 USB-TTL 先设置为慢速自动输出：在当前波特率发送 `LOG HI91 ONTIME 0.5`、`LOG ENABLE`，再设置 9600（如果尚未设置），切换串口助手到 9600 后发送 `SAVECONFIG`、`REBOOT`。

此模式不产生触发，持续监听数据，显示 01 或 02 的有效帧数和姿态。分别测试两只，核对地址、二极管方向、上拉及数据解析。仅仅在同时接两只时偶尔收到有效帧，不能证明总线通信可靠。

结束单机诊断后，逐只重新设置并保存 `LOG HI91 ONMARK 1`，再恢复 `TEST_MODE 1` 并接入 D6、D7。

如果完全不增加 SYNC_IN 又必须共用这一组 TX/RX，就需要厂家提供当前固件的带地址查询协议。另一种布线方案是让两只 IMU 的 TX 分别接主控不同 RX，取消回传汇接；本程序不采用这一方案。

## 故障排查

| 输出 | 检查 |
|---|---|
| 一直 `bytes=0`，最后 TIMEOUT | IMU 是否为 9600、供电、D10、二极管方向、SYNC_IN 脉冲、电平 |
| `UNSOLICITED_BYTES` | 仍为自动输出、配置响应未结束、线路噪声，或上一帧延迟到达 |
| `WRONG_ADDRESS` | D6/D7 接反、实际地址不同、或两只没有正确进入触发模式 |
| `ADDRESS_LAYOUT_OR_CONFIGURATION` | 固件不是新版地址布局，或设备地址不是 01/02 |
| `CRC_ERROR` | 波特率不一致、两只同时发送、低电平不够低、供电或接线问题 |
| `RX_OVERFLOW` | 主循环未及时读数据、仍在高速主动输出、额外耗时功能 |
| 程序报非 ATmega328P | 选择的不是经典 Uno 板，或实际使用 Uno R4 等其他型号 |
