# PX-6AX → AW86234 触觉反馈实现（2026-09-30）

维护位置：`D:\aw86234-testbench`。本功能使用 ESP32-C6 测试板，未移植到尚在整改的 S3 手套核心板，也不修改遥操作机器人的控制律。

## 直接使用

1. 运行根目录 `launch.cmd`，顶部连接 **COM32**。
2. 打开新增的「触觉反馈」页：传感器 **COM7**，地址 **3**，反馈 **CH4**。最高电平默认 **40**。
3. 先保持传感器无接触，点击「开始触觉反馈」，再轻压、逐渐加压、松开。压力对应持续振感，接触开始有短促增强。
4. 按 Esc、顶部「全部停止」或页内「停止触觉反馈」结束。断开、退出、输入异常都停止；修复后必须重新点击开始。

GUI 只将一个传感器映射到一个明确选择的指尖，通道不随顶部多选变化。不得同时运行 CLI 与 GUI 占用同一串口。

也可运行根目录 `launch_tactile.cmd` 做 60 秒 COM7→CH4 演示，或在 `host` 下：

```powershell
python -m awtest.tactile --sensor-port COM7 --device-id 3 --allow-err-len --motor-port COM32 --config tactile_com7_ch4.json --seconds 60 --log tactile_last_run.jsonl
```

不指定 `--motor-port` 时只读传感器并计算电平，不驱动马达。`--demo` 生成离线测试输入，禁止同时指定马达串口。`--seconds` 控制 CLI 时长，GUI 持续到停止。

## 实际硬件与证据边界

- 本机枚举 COM7 为 CH343，COM32 为 ESP32 USB 串口。只读探测确认：PX 地址3，返回 `aa550d000300fbf0030000030001000000ff`，完整长度、设备、寄存器、LRC 均正确；合力为0，状态为1。
- `--allow-err-len` 只允许这个已验证转接板的状态1兼容，仍校验所有其他字段。默认底层驱动严格拒绝非零状态；GUI 为本机配置勾选了兼容项。
- 原固件1.0.3，CH4–CH7在线（0xF0）。新增协议需要1.0.4和 `CAP_TACTILE`，旧固件明确拒绝进入触觉模式。
- 历史实测1040 LRA谐振约166.7–169.0Hz；本功能以168Hz为初始参考并启用芯片跟踪。电平不是加速度或位移，舒适范围仍须按安装方式标定。
- 测试结果见本任务 `output/tactile_chain_20260930` 日志；协议回读不能证明机械振幅或人体感受，也不是端到端机械延迟测量。

## 输入、算法与参数

`Sample(sensor, sequence, acquired, force, taxels)` 为稳定的无GUI接口。`force` 是牛顿单位 `(Fx,Fy,Fz)`，Fz正方向为压入；`acquired` 为本机单调时钟。其他机器人触觉来源可构造 Sample，再调用 Mapper、Session。不得将未换算的ADC原始量直接当牛顿输入。

PX单路转接板使用921600/8N1、fin_master读命令0xFB，合力起始0x3F0，Fx/Fy为int8，Fz为uint8，0.1N/LSB。按请求时间保守计算输入年龄，不以迟到的接收时间刷新新鲜度。读事务超时75ms，错误立即终止，不继续输出上次值。无需修改传感器配置或自动零点标定。

每通道处理：

1. 减去显式配置的三轴空载偏置。无自动跟踪零点，避免把持续抓握学成零力。
2. 使用随采样间隔变化的15Hz一阶低通，`alpha=1-exp(-2π·15·dt)`。
3. 接触迟滞：超过0.4N进入，降至0.2N退出。退出后电平直接归零。
4. `u=clip((Fz-0.2)/(F_full-0.2),0,1)`；持续电平 `Lmin+(Lmax-Lmin)*u^gamma`。默认满量程10N，gamma=0.6，Lmin=18；GUI/本机配置 Lmax=40，算法允许至60。
5. 首100ms附加 `8*exp(-接触年龄/35ms)`，然后逐通道截断，限制变化速率500电平/秒。起始阶段可以低于起振阈值，以限制跃变；标定后可调整。
6. 可选切向风险提示默认关闭。开启后，切向/法向比>0.6且切向变化率>1N/s持续至少30ms，叠加小幅8Hz提示。它只是启发式“切向风险”，**不是经验证的滑移检测或材质识别**。
7. 按 `sqrt(7200/sum(L²))` 必要时缩放并向下取整；固件再次检查单路≤60及平方和≤7200。该预算是驱动电平代理量，不是实测电流限流器，不替代供电测量与硬件保护。

这些参数是可执行的工程起点，不是论文证明的最佳感知参数。压力编码有依据，但未经本机人体试验，不能宣称可区分固定档数、真实还原材料、或误差/延迟达某指标。

## 多指与52点空间映射

默认一个传感器对应一个马达；不把同一指尖的52个采样点自动当成五个手指。多传感器使用不同 `sensor` ID和唯一通道的Route，所有映射输入都必须保持新鲜。

若确需把单个传感面分区反馈，Route显式给出不相交的零起始 `taxels` 索引，CLI用 `--points 52`。以区域正法向测点和占全表面正法向测点和的比例分配**已测合力**，不把测点值求和冒充另一种标定合力。分区只是触觉空间编码，需要用户确认区域对应身体位置。分布力从0x40E开始，与合力一次连续读取；本机已完成合力与52测点一次连续读取的只读核验。

## 新协议与停止保证

能力位 `CAP_TACTILE=1<<19`，命令 `TACTILE_FRAME=0x4F`，12字节：

| 偏移 | 内容 |
|---|---|
| 0 | action：0=START，1=UPDATE |
| 1 | 固定会话通道mask |
| 2–3 | uint16LE序号，允许65535→0 |
| 4–11 | CH0–CH7电平，未选通道必须为0 |

成功应答回显完整12字节。START必须全零，且不能接管其他正在播放的通道。UPDATE要求已有同mask会话、严格递增半区序号、合法电平和预算；重复/倒序帧不续约，过期UPDATE不能重新启动。主机检查完整回显。

固定CONT跟踪、WAIT_NUM=0、DRV1_TIME=255、DRV2_TIME=0，1.0.5中静默START不GO，零电平执行STOP，零→非零先写0x1C低7位再GO以重新建立跟踪；持续非零更新仅改幅度、保留TRACK_EN，不重复GO。多路I2C并非物理同时更新；**先完成所有降幅，再执行升幅**，避免过渡态超出总预算。任何写失败撤销会话并尝试停止整组。

主机最大输入年龄150ms；固件仅新合法TACTILE_FRAME续约300ms，普通PING和LIVE_KEEPALIVE不能续触觉会话。300ms是固件调度阈值，实际停止还包括调度/I2C/马达余振时间。STOP/STOP_ALL、配置变化、故障均撤销会话，失败的STOP由现有安全任务重试。持续硬件总线故障仍须使用物理电源开关。

## 标定步骤

1. 无负载采样数秒，确认基线和噪声；必要时将三轴均值写入配置的baseline。不要在按压状态清零。
2. 只使用一个马达，从低电平比较起振和可感知阈值，按实际佩戴方式设置min_level和max_level，初次建议不超过40。
3. 根据机器人/物体任务选择force_full_n，使正常抓握不一直饱和。gamma<1扩大轻力差异，gamma=1为线性电平；无需把某篇心理物理指数直接当通用真值。
4. 记录轻、中、重压力及松手结果，检查日志中输入力、接触状态、电平与饱和。再做随机顺序盲测确认可辨性。
5. 单路完成后才按明确通道表增加多指，测量电源电流与长时间温升。平方和预算只提供软件约束。

## 2026-09-30 实测反馈改进（1.0.5）

用户反馈强按时偶发弱振/无振。本轮找到的候选机制是：旧触觉会话在电平0时GO，松手后仍保持跟踪，再接触仅写幅度，没有重新起振。[AW8623X官方V1.4资料](https://doc.awinic.com/doc/202508/539b1411-cb0a-4800-840d-ff2fc241eb09.pdf)说明跟踪利用BEMF；零激励下跟踪条件不足是工程推断，尚未用机械测量确认它就是全部哑振的根因。

修正为静默START、零电平STOP、零到非零显式GO；常规连续非零更新不重启。硬件故障仍撤销会话，不以重启绕过保护，输入150ms与固件300ms时限不变。

新增触感（压力归一化u范围0–1，包络相位按每帧dt累积，接触时重置）：

| 模式 | 行为 |
|---|---|
| 连续压力 | 保留原压力幅度、接触增强 |
| 力度顿挫 | 1.5+6.5u Hz，50%占空；轻压慢、重压快 |
| 柔和呼吸 | 0.5+u Hz余弦包络，40%–100%幅度 |
| 双击节奏 | 1+2u组/秒；每组相位0–0.2与0.35–0.55输出 |

所有模式共享幅度上限、能量预算与松手归零。节奏不是马达载波频率，载波仍采用约168Hz起始频率并自动跟踪。模式需停止后选择再开始，防止无提示的运行中切换。

## 2026-10-01 清脆短击与连续弱振改进（1.0.6，当前版本）

用户实测1.0.5：连续压力有时微振、有时很强；双击与顿挫拖尾。上一版零→非零GO不足以消除症状，本轮没有将软件测试通过当作手感解决证据。

### 实机排查

先比较缓升10/20/30/40与直接40起振：两者在保持电平40后，CONT频率计数0x26/27均从起始值跳到raw约1188，即按项目既有CONT换算基准384000得到约323Hz。STOP后0x09为0，不支持“旧STOP位混入GO”的假设。之后改成一次连续读取两字节，排除独立读取高低字节的撕裂，仍复现。

单变量对照：跟踪开、40/60电平仍出现约320Hz读回；跟踪关、宽度106时稳定约156Hz；宽度80时约160Hz。改变F_PRE到130/132/134没有显著改变上述计数，因此未将F_PRE名义值直接当成固定驱动的实际频率。宽度32/48/64又出现约320Hz计数，因此没有采用它们。

这些是芯片内部计数，不是示波器/加速度计得到的机械频率或振幅，可能包含谐波识别等因素。本轮证据定位到CONT跟踪/驱动参数路径，不能据此声称全部弱振物理原因已完全确定。

### 当前实现

- 触觉专用会话关闭TRACK_EN，采用已在本板比较的DRV_WIDTH=80、WAIT_NUM=0、DRV1_TIME=255、DRV2_TIME=0，保留原峰值60与平方和7200预算。普通实时调试的跟踪模式不改。
- 连续非零阶段BRK_EN=0且BRK_TIME=0；只有输出降到零时配置BRK_TIME=4并打开BRK_EN后STOP。下一次GO前清掉制动。四个制动半周期名义约12ms，尚无机械余振测量。
- 下一次升幅前最多等待16ms制动窗口，并对零电平通道关闭制动后STOP，避免旧制动尾段与升幅向量重叠。保护没有扩大幅度/输入超时/数据租约；硬件故障仍撤销整组会话。
- 顿挫和双击改为18ms逻辑脉冲，在约50Hz主机采样下通常占一个20ms帧；双击第二击在首击后约80ms。取消短击的幅度慢起，保留限幅。重复频率仍随压力变化，轻压不再产生数百毫秒长的50%占空嗡鸣。
- 首帧在静默START成功后立即发送，避免初始化消耗首个短击；重复render仍不续租。诊断读取避开短击ON阶段。
