**§5 待回填项（已有结论的部分）**

* F0 实测值与标称偏差 → 见上表（1040 标称 170.5 Hz，实测 166.7~169.0 Hz，1~2%）。
* 8 路在线时的 CHIPID 与 VREG → 实际是 **4 路 0xF0**，CHIPID `0x2340`、VREG 全部 OK。
* 上游 I2C 上拉 → 存在（4.7 kΩ），无需补焊。
* C-1 / V-1 / V-2 / V-3 → 全部排除或已硬件修复（见上表）。
* 仍未回填：CONT 播放中改幅度的即时生效性、RTP 经 TCA 的实际可行性、
  `max_simul_full_amp` 最终取值。

**★ 新增的固件侧已知陷阱（已修，但要记住）**

1. **F0/RL/VBAT 检测必须在"普通模式"下做** —— `0x46` 的 WAKE/STANDBY 只要置 1，
   `DETRD1~3` 就恒读 0（RL 恒 0 Ω、VBAT 误读成 VDD 的一半）。
   而 `aw_softrst()` 会置 WAKE=1，所以"软复位 → 阻抗检测"必然失败。
2. **RL 检测要显式设 `D2S_GAIN`**（手册第 3 步），并按检测时实际用的增益换算。
3. **`MAINLOOP` 在 `0x16`，不在 `0x15`** —— 写错的表现是"波形只播一遍"且无任何报错。
4. **`WAVDAT_MODE`（`0x46` bit1:0）对 RAM/TRIG/CONT 播放同样生效**，
   必须与波形生成采样率一致，否则驱动频率成倍偏移。
5. **CONT 下 `SYSINT.DONEI` 不是"播放结束"**（驱动段一结束就置起，芯片仍在输出），
   据此判结束会误报并**连带解除播放安全超时**。
6. **持续振动必须用 CONT + `WAIT_NUM=0`**；用 RAM 循环波形库会"一块一块"。

## 1. 🔴 阻断级硬件闸门（**不过就别写代码/别调试**）

按顺序确认，任何一项不过就先处理硬件：

| 顺序 | 检查项 | 怎么查 | 期望 | 不过的后果 | 实测结论 |
|---|---|---|---|---|---|
| 1 | **SW2 的消抖电容 C27** | 万用表量容值 / 看丝印 | **≤10 nF** | ≥0.1 µF → IO9 strapping 被拉低 → **每次上电进下载模式，固件根本不运行**（"烧录成功但毫无反应"的头号原因） | 【待填】 |
| 2 | **马达回路的 16 颗串联电容** | 量值 + 目视贴装 | **0 Ω 或未贴** | 非 0 Ω → 马达上分不到电压，**完全不振**；F0 检测与自动刹车也失效（0.1 µF 在 200 Hz 约 8 kΩ，而马达只有 6~8 Ω） | 【待填】 |
| 3 | **J1 跳线** | 目视 | `3-5 + 4-6`（LP，推荐）或 `1-3 + 2-4`（HP）；**不能两组都插** | 不插 → TCA 悬空，完全无法通信；两组都插 → IO2/3 与 IO6/7 短接，可能损坏 | 【待填】 |
| 4 | **TCA 上游上拉（V-1）** | 断电，量 J1.3 / J1.4 对 3.3 V 电阻 | ≈4.7 kΩ | 无穷大 → 400 kHz 必然失败，需内部上拉降速到 100 kHz，或补焊 4.7 kΩ | 【待填】 |
| 5 | **Q1 的 S/D 朝向（V-2）** | 对照 AO3401A 规格书 | S 接输入、D 接负载 | 接反 → SW3 断电失效（"拔电重插"无效，只能靠软复位） | 【待填】 |
| 6 | **TRIG 下拉（V-3）** | 目视 IO18~22 / IO14 对地电阻 | 10 kΩ（未补则记录风险） | 无下拉 → 上电到固件配置下拉之间可能**误触发** | 【待填】 |
| 7 | **LED1/LED2（C-2）** | 目视 R1.1 / R22.1 | 已接 +3.3V 或 GPIO | 灯不亮 → 别拿 LED 当"板子活着"的判断依据 | 【待填】 |

**固件对应的应对**（已实现）：

* 闸门 1：无软件对策。固件层面**无法绕过**，只能先换电容。
* 闸门 2：提供"马达通路自检"——`SELFTEST` 里读 VREG 是否正常、读 LRA 阻抗 `RL`；
  `F0` 失败时给出明确诊断文案。**VREG 正常但 F0 超时**就是 C-1 的典型签名。
* 闸门 3/4：`BUS_PROBE` 运行时自动探测 LP→HP；100 kHz 不通时自动尝试内部上拉，
  成功则在 `caps bit14` 标记"降级运行"并在上位机顶部显示黄色横幅。
* 闸门 6：`app_main()` **第一件事**就是 `board_trig_safe_init()`（输出低 + 内部下拉）；
  这段窗口无法消除，只能尽量缩短——**已记录为已知风险**。
* 闸门 7：不用 LED 做状态判断，连接状态以串口通信为准。

## 4. 本实现的已知限制（已在代码/界面中显式表达）

| # | 限制 | 原因 | 软件里的体现 |
|---|---|---|---|
| 1 | **RTP 48 kHz 不可用** | TCA9548A 与 ESP32-C6 的 I2C 都只到 400 kHz（Fast mode），48K 需 ≥1 MHz | `caps bit13 = 0`；`WAVE_BEGIN`/`SET_RTP_PARAMS` 返回 `ERR_UNSUPPORTED`；界面置灰并写明原因 |
| 2 | ~~**CH5/6/7 硬触发无法独立**~~ **已不成立** | 旧版硬件三者共用 `GPIO14`；**新硬件每路一条独立 TRIG**（CH0~CH7 = IO18/19/20/21/22/14/IO0/IO1，各带 4.7 kΩ 下拉） | 固件 TRIG 表已改为 8 路独立；`BOARD_TRIG_SHARED_MASK = 0x00`；单 bit 掩码实测 `started_mask` 一一对应 |
| 3 | **无硬件复位** | 8 颗 AW86234 的 RSTN 全部并到 VDD | `caps bit11 = 0`；复位只能软复位（`0x00=0xAA`）或人工拨 SW3；`AW_SOFTRST` 后自动重放 Profile |
| 4 | **无 GPIO 控制的马达电源** | Q1 栅极由 SW3 手动控制 | `caps bit10 = 0`；界面"断电重启"置灰并写明原因 |
| 5 | **µs 级时序只能由固件本地生成** | USB-CDC 往返延迟是毫秒级且抖动大 | `TRIG_PULSE`/`TRIG_PATTERN` 用忙等（`esp_rom_delay_us`）实现；上位机只下发参数、读结果 |
| 6 | **波形库可用容量 1024 字节**（`base_addr = 0x800` 之上） | 协议文档内部有"约 2 kB"的说法，与组库算法矛盾；按算法与附录 D 第 12 条实现 | `WAVE_BEGIN` 回报 `max_total_samples`；上位机提前拦截超限。**联调时需用真实芯片读写验证**（见 `协议一致性说明.md` §2.2） |
| 7 | 单通道波形会话缓冲 3 kB × 8 通道常驻 | 便于多通道并行下载（协议允许） | 实测 BSS 占用约 30 kB；若 RAM 紧张可改为单会话共享池 |
| 8 | 上电到固件配置 TRIG 下拉之间仍有误触发窗口 | V-3，硬件缺下拉；软件无法消除 | 已记录为已知风险；彻底解决需硬件补 10 kΩ 下拉 |
| 9 | **CONT 的数据手册默认参数不适合"持续振动"** | `DRV1_TIME=4`/`DRV2_TIME=6`/`BRK_TIME=8`/`WAIT_NUM=6` 会让输出变成"带刹车段 + 段间停顿"的断续脉冲（`WAIT_NUM` 是主要元凶） | ASCII `cont` 已内置正确参数；**GUI 的 CONT 参数页仍显示手册默认值**，照默认值下发就会重现"一段一段" —— 待加"持续振动"预设或对 `WAIT_NUM>0` 提示（见实测记录 §2.20） |
